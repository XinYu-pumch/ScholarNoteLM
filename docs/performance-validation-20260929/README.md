## 性能

同一台电脑、gut 项目（105 篇文献），通过现有 research-cli 读取。数字为后端接口耗时，包含 CLI/服务进程启动，不是完整界面首屏时间。详细测量见 `timings.json`。

| 问答材料目录 | 1.88–2.69 秒 | 0.15 秒左右 |
| 文献索引状态 | 1.47–1.64 秒 | 0.13–0.15 秒 |
| 项目概览统计 | 1.75 秒左右 | 0.54 秒左右 |
| 综述撰写状态 | 1.44–1.51 秒 | 0.24–0.25 秒 |

首次计算或材料变化后仍需完整检查；问答对话现独立加载，不等待材料目录完成。问答空闲更新由原来的完整对话（此次样本约 2.48 MB）改为约 123 B 的版本/任务状态响应，有变化才读取正文。

导航不再触发全工作区同步；相同 XML 不再反复写入。下载轮询由应用与页面共享，保留恢复任务及自动转换衔接。空闲状态降低检查频率，任务活动时恢复较快更新；检测到相关任务状态改变后联动刷新材料数据。隐藏的综述撰写页仅保留必要任务状态，正文按需加载。

缓存恢复文献筛选、检索页签、综述页签与工作区、问答草稿及阅读位置。已有内容在后台核对期间保留；文献准备状态尚未读取时使用待核对状态，不冒充零篇或全部最新。

## 缓存失效与发送前验证

- 后端摘要缓存位于应用的 `cache/status-snapshots/`，按项目实际目录隔离，可随时删除重建，不修改原文或索引。
- 每次使用摘要前核对 XML、PDF、Markdown、图表文件、转换元数据、清理/重建标记、SQLite 主文件及 WAL、配置文件和代码版本的文件身份。
- 文件身份包含设备、inode、大小、纳秒修改时间和变更时间。替换、删除、新增，以及只恢复修改时间的内容变化均使摘要失效。
- 计算期间依赖发生变化会重试；持续变化时返回待更新错误，不发布假定为最新的摘要。
- 前端操作与后台任务变化触发对应缓存失效；跨项目隔离，旧请求不能覆盖失效后取得的新结果。
- **qa.start、问答 worker 的 current_signature/corpus，以及综述实际生成使用原有完整校验路径。显示缓存不能授权发送、不能绕过原文/索引/Embedding 配置检查。**
- 问答 inventory 的计数读取不再取出向量 BLOB；实际检索仍按原有路径读取有效向量。
