# 文献问答（当前开发版）

更新：2026-09-28。主题问答采用“小综述”流程，与综述撰写共用正文召回、关联图表和引用渲染。具体上下文协议见 [QA_CONTEXT.md](QA_CONTEXT.md)。

## 使用流程

1. 在文献库完成文献准备和索引，在设置中保存并验证 Embedding 配置。
2. 选择项目文献范围和回答模型。需要实际图像输入时，在设置 → 模型与服务 → 可用模型的对应行勾选“支持图片”并保存。
3. 发送问题。首次规划同时结合正式对话历史判断意图：闲聊或澄清直接回复；纯改写保留历史回答与引用绑定；依据追问优先读取历史实际引用；新的研究问题生成具体 query。
4. 需要检索时，每个 query 在所选文献的有效正文向量中按相似度召回 topK。按稳定 ID 合并命中块，并补入位置关联的完整表格、图片和附近文字。标题与章节路径只保留为来源信息，不拼入向量输入。
5. 规划模型根据累计材料判断覆盖是否足够。达到最少检索轮数且材料足够时写回答；不足且未达上限时补查询；达到上限时基于已有材料写回答，并说明材料局限。

默认每个 query 8 块、每轮最多 3 个 query、最少 1 轮、最多 3 轮；按用户设置生效。纯改写、闲聊、只读取历史依据不被强制凑检索轮数。应用不向回答模型发送输出 token 上限。

自动挑选整篇全文并补入主题问答材料池的功能、提示和开关已删除。历史证据按需取回仍保留。输入区提供“主题问答”和“项目概览”两种模式；“单篇精读”已停用，旧运行只作为历史问答显示。

## 清洗、检索与来源

- PDF 使用 Marker 转换，并固定仅清洗参考文献。短正文、图注、表格保留。
- 召回排除少于 100 字符的 heading，保留长 heading；不使用 BM25、MedCPT 或本地重排模型。
- 图表作为材料不等于必须插入正文。模型判断展示必要性；生成表可摘取或合并材料，原图原表使用资源块。
- 未实际发送图片时，不允许把文字中的图号当作已经看图。勾选视觉能力只是配置，不能证明模型理解正确。
- 引用内部保留证据 ID；同一处连续引用按 PMID 去重，不删除不同句子各自的引用。图表编号、正文交叉引用与导出使用统一渲染逻辑。
- 主题问答执行程序结构与引用范围检查，不追加 LLM 事实后验证。结构通过不表示人数、物种或实验条件已被正确理解。

## 上下文、重试和对话管理

用户问题、追问和成功的正式回答组成对话历史。历史整个材料池不自动重发；`read_previous_evidence` 按需读取实际引用的原文和图表，并重新绑定本轮编号。纯改写不会为填补内容新增事实。

失败回答的“重新生成”或“继续未完成步骤”在原消息位置显示新尝试，日志仍按运行保存。可继续的检查点必须与当前输入和来源匹配；不匹配时需要重新生成。模型身份按实际端点、模型、温度、供应商参数和当前模型的图片能力比较；更换密钥、调整超时、复制相同配置、切换其他模型的图片开关不使新任务检查点失效。恢复时并发数和未开启 RCS 时的候选数可变，检索参数、实际模型、材料和问题仍须匹配。旧检查点通过原哈希精确验证后保留别名，继续复用已完成调用和证据卡；若旧密钥或历史模型列表已丢失、无法验证原哈希，则保守拒绝续跑，已有回答保留。Embedding 的密钥仍需通过连接验证。

左右切换对话或离开页面不隐式取消任务，不同对话可以同时生成。停止只作用于目标对话。对话列表支持右键重命名、复制、删除，以及选择/全选批量删除。顶部“对话目录”可按提问编号和文字搜索定位，也可回到最新。

## 设置

- 模型与服务：模型启用、默认模型、支持图片、连接/图片测试集中在模型行。
- Embedding 模型：启用已验证配置；高级参数中的 RPM/TPM 同时用于文献和 query 向量请求。“召回与重排”设置已删除。
- 文献问答：配置检索轮次、topK、每轮 query 数及规划/回答模型。项目概览保留自己的阅读设置。
- 模型请求默认跟随当前系统 HTTP(S) 代理；没有代理时直连，本机模型保持直连。系统代理开关或地址变化后，新请求和连接重试读取最新设置，不需要重启应用；已建立的流式连接不强行迁移。检索助手、阅读对话、综述和连接测试使用相同策略。

## 日志与验证

`<项目>/qa/threads/` 保存对话；`<项目>/qa/runs/<runId>/` 保存输入、进度、模型请求与响应、证据快照、`history-evidence.json` 和 `answer-bundle.json` 等产物。日志不包含 API 密钥。导出位于项目 `qa/exports/`。

可复现检查使用隔离项目和本地模型模拟服务：

```sh
runtimes/retrieval/bin/python -m unittest discover -s services/downloader/tests -p 'test_qa*.py'
runtimes/retrieval/bin/python scripts/test-qa-mini-review-integration.py
runtimes/node/bin/node scripts/test-qa-mini-review-ui.mjs
runtimes/node/bin/node scripts/test-conversation-ui.mjs
```

程序回归不代替学术质量评估。人工测试问题与追问见 [gut 问答评估](GUT_QA_EVALUATION.md)。

## 请求日志存储

新任务的冻结输入 `input.json.gz`、请求 `*.prompt.json.gz`、返回 `*.response.txt.gz` 使用无损 gzip，问答推理日志同样压缩。直接在生成时生效，不需要维护脚本；重试、读取与历史稿件上下文兼容旧明文记录。任务状态、检查点、正文和模型协议不变，正在追加的 worker 日志保持普通文本。


### 双语行为

每个对话独立保存回答语言。规划、证据评估、直接回复、综合撰写和格式修复使用对应语言提示词，原文及协议字段保持不变。新轮次冻结语言；重新生成、检查点续跑及分支沿用原轮次语言。切换界面语言不改变对话设置。
