# PrimaryMN Embedding 实测与完整性验证

日期：2026-09-29。使用开发版现有配置 Pro/BAAI/bge-m3，客户端上限 RPM 1800、TPM 450000。密钥仅从现有配置读取，不包含在报告中。

## 最终结果

- 当前文献 230 篇：180 篇全文、50 篇摘要来源。
- 有可用文本并完成索引的文献 216 篇；另外 14 篇没有可生成 chunk 的文本，具体 PMID 见 completeness-audit.json。这不属于漏算向量。
- 当前 chunk 16772 个，唯一输入 15187 个；1585 个重复文本 chunk 复用相同向量并保留各自归属。
- Chroma 实际向量 16772 条，1024 维；缺失 0、无效 0。
- 按每个 chunk 的内容指纹、文献归属、输入签名和向量数值，逐项对比 SQLite 缓存与 Chroma，全部通过。
- 本地 bge-m3 tokenizer 统计：全部 chunk 共 2138634 token，最大单块 3286 token。这里包含重复 chunk；实际 API 输入可去重。

## 分批与并发实测

首先发送六组真实输入，8/16/32 段各两组。延迟 0.308–0.701 秒；32 段的两组实际输入分别为 5020、4826 token。4 并发足以超过可用 TPM，无需先大幅提高并发。

| 调度方式 | 实测范围 | 滚动 60 秒 token 中位数（在请求时采样） | 最大滚动 60 秒 token |
|---|---:|---:|---:|
| 每段固定预留 8192、usage 回补 | 14010 次输入，因磁盘不足中断 | 288475 | 350767 |
| tokenizer 精确计数、余量和窗口修正 | 8000 个输入完整复测 | 426651 | 449929 |

两个范围的文本分布不同，因此此表说明实际额度利用率，不是完全同输入的严格速度倍率比较。

最终 8000 输入的复测：

- 1138863 个实际输入 token。
- 267 个 HTTP 请求，全部 200，0 个 429。
- 批量动态范围 1–32；并发根据延迟与预算调整，本次稳定在约 2。
- 最大滚动 60 秒请求数 108，远低于 RPM 1800。
- 总耗时 143.85 秒；请求区间 143.02 秒。
- 每个发送时间点核对过去 60 秒总量，TPM ≤450000、RPM ≤1800 均通过。允许短时突发，因此不能用总 token / 短任务总时长替代滚动窗口限速审计。
- 此轮不改写项目缓存或 Chroma，只验证所有返回向量的数量、维度和输入对应关系。

## 测试中发现并修正的问题

1. 固定 8192 预算在请求未返回时占用过多额度。实际 token 常远小于预留，导致持续吞吐停留在约 29 万 TPM。
2. 使用官方 BAAI/bge-m3 tokenizer，本地六组计数与供应商 usage 完全一致。采用实际 token ×1.02 向上取整，再加每段 2 token 余量；输入未截断，超过单条限制明确报错。
3. 首轮精确计数基准中，实际发送时间滚动窗口曾到 453548 token，超出客户端目标约 0.8%。原因是额度预留早于工作线程发出请求。已把额度记录时间更新至实际发送前，并将保留窗口延长至 61 秒；最终复测最大 449929。初轮失败结果保留在 verified-benchmark，未删除或作为通过证据。
4. 本机磁盘在全量任务中途耗尽，进程退出。清理了本项目可再生成的 Rust 增量编译缓存。确认进程终止且 13990 个唯一输入已落盘后，才创建恢复任务；补发剩余 1197 个输入，完成全项目索引。20 个退出前已返回但未提交的输入可能重新请求；没有把未保存的结果算作完成。
5. 原索引发布每篇前后扫描全库。增加按 PMID 刷新路径，保留文件核对、材料版本、纳入集合及最终发布校验，避免重复扫描其他文献。

## 采用的调度方法

- RPM 和 TPM 使用同一个跨进程 SQLite 配额账本，发送前原子预占；结束后按真实 usage 校准。
- 保守模式按每段 8192 预算；验证模式检查 tokenizer 文件 SHA-256、模型、地址和版本标识，再用校准计数。
- 根据剩余额度装入完整 chunk，余量不足时缩小批次；不截断 chunk。
- 跨文献队列按正文 hash 去重，请求完成立即补位，不等待整组全部结束。
- 根据近期开销调整并发，内部保护上限 16；本次批量保护上限保持已实测的 32，已能充分利用 TPM，无需继续放大。
- 429/5xx 沿用共享退避；usage 超过精确预留时停止加速，保留已完成缓存，要求重新校准。
- 成功向量立即保存。发布文献索引前复查材料和归属，最终审计每个 chunk，而不是只检查任务是否显示完成。

本轮新增的动态模式通过后台 vector.start 的 adaptive=true、tokenBudget=verified 启用。常规 UI 的手动参数和默认启动方式没有切换为自动模式，也未重新打包安装版；本报告验证的是已实际运行的后台调度方案。
