# 紧凑操作菜单与三条任务中心

2026-09-29。按已确认方案修改界面与任务展示；不删除下载历史、不改下载来源、转换或索引算法。

## 已实现

- 文献库四个“更多”统一为独立挂载到 body 的固定浮层；不再使用 details 内的原生 popover/Grid 组合。宽 248px，内容决定高度，菜单行约 36px；PDF 三行菜单实测约 130px 高。
- 菜单紧贴触发按钮，自动避开窗口边缘；内容、窗口尺寸及滚动变化重新定位。移除标题，保留数量与危险操作分隔；浅色/深色使用相同语义色。
- 同时只允许一个菜单打开；点击外部、Esc、执行操作均关闭。方向键导航跳过禁用项；修复 WebKit 鼠标打开菜单后焦点仍在外部导致 Esc 无效的问题。
- 任务中心始终保持 PDF 下载、Markdown 转换、检索索引三条，顺序固定，按项目隔离。不存在任务时显示“尚未开始”；请求期间显示“读取中”。
- 下载选取当前项目最新批次；若旧批次仍运行、排队或暂停，优先保留其控制入口。转换和索引使用后端各自的当前 job。
- 重试未获取项创建新批次，只选择当前集合中仍无 PDF 的失败/延期文献；新一轮有独立分母。原任务暂停后继续仍使用原 ID 与进度。
- 已结束且存在失败/延期的任务显示“已结束 · 部分未完成”；进度条代表处理进度，不代表成功率。
- 来源、逐篇结果、报告及日志入口收纳到默认折叠的详情。下载来源按本轮成功条目统计；原有 Bloom 补救入口移入下载详情。
- 一键更新的等待状态映射到三条任务，不增加第四条。当前流程提供停止入口；侧栏计数与任务中心共享等待状态规则，只统计运行/排队/正在停止及自动接续等待的类别。
- 历史下载数据库与报告保留；任务中心不展开历史批次列表。
