# 系统资源与项目文件

系统资源仍由安装目录管理：`data/reference/` 保存 JCR、MeSH 和 Sci-Hub Bloom；运行时、本地模型与依赖留在安装目录。`data/research/` 仅保存共享服务配置和系统状态，`config/storage.json` 保存工作目录与项目文件夹映射。用户密钥不会复制到项目数据库。

设置 → 外观与存储：选择项目工作目录或输入绝对路径，点击“保存并迁移项目”。默认工作目录为安装目录下的 `workspace/`。迁移前要求没有正在执行的检索、聊天、下载；先复制并逐文件校验 SHA-256，成功后切换路径并删除旧位置的项目文件夹。目标目录同名项目不会被覆盖，失败保留原位置。暂停的下载任务在迁移后可以继续。

新建项目分别填写显示名称和文件夹名。文件夹名允许 1–64 个中文、英文字母、数字或下划线，不允许空格和连字符；排除 Windows 保留名，英文不区分大小写判重。项目 ID 与文件夹名是不同概念，调用 RPC 时使用项目 ID，文件路径通过存储映射解析。

```text
工作目录/
  gut/
    project.json                  # 项目信息及编辑状态
    README.md                     # 目录说明
    archive/markdown/<PMID>/<版本>/ # 移出集合的 Markdown、图片及转换记录备份
    pubmed/
      current.xml                 # 当前检索式合并、去重、筛选后的文献
      queries/                    # 各检索式的原始 XML 与执行历史
      snapshots/                  # 合并集合历史快照
      objects/                    # 按内容哈希共享的 XML gzip
      exports/                    # XML 导出
    pdf/<PMID>.pdf                # PDF 原文
    abstracts/<PMID>.md           # 下载失败时保存的 PubMed 摘要
    logs/<批次ID>/                # 下载报告、逐篇日志、批次快照
    markdown/                     # 清洗后的全文；raw/ 原稿与 assets/ 图片
    vectors/                      # chunks.sqlite3、源文本快照、索引状态、按需 exports/
      resource-assets/            # 图表图片快照
    notes/notes.json              # 阅读笔记
    review/                       # 综述工作区、大纲、正文及生成来源
    reader/                       # 单篇对话、阅读位置和共享全文快照
    qa/                           # 问答对话、运行证据和导出
    packages/current-literature.zip
    metadata/
      research.sqlite3            # 此项目的检索、成员关系、助手对话
      downloads.sqlite3           # 此项目的任务、尝试历史与文件登记
      downloads/<PMID>.json       # 来源、版本、校验值
      zotero-imports/<任务ID>/     # 导入快照、进度和报告
```

项目运行数据独立保存在各项目的 metadata 数据库；JCR、MeSH、模型配置等仍共享。文件登记使用项目相对路径，更换工作目录不破坏 PDF 和 XML 关联。

## 新项目直接使用的紧凑存储

正常生成流程自动压缩综述/问答请求审计记录、冻结输入以及下载报告；读取兼容旧明文格式。下载报告在界面中直接解压显示，外部打开时才生成 `logs/<批次ID>/exports/download_report.txt`。

PubMed 查询、抓取批次和合并集合通过清单中的 `xmlPath` 引用 `pubmed/objects/<SHA-256>.xml.gz`。重复的完整 XML 原始字节只存一份，历史清单仍各自保存；读取验证原始字节哈希，当前集合和显式 XML 导出保留普通文件。整个项目移动时相对引用继续有效；不要单独删除共享对象目录。旧 `raw.xml` / 快照 `pubmed.xml` 兼容读取，更新不批量改写已有项目。

macOS/APFS 上的新向量图片快照优先通过 `clonefile` 共享原图的数据块。它是写时复制的独立文件，不是硬链接；原图原地编辑或删除后，旧证据仍保留旧图。按文件长度求和不能反映这种底层共享。项目迁移也尝试写时复制，不支持或跨卷时使用普通复制并逐文件校验，可能增加实际占用但不影响完整性。其他存储优化不依赖 APFS。

## 项目选择与删除

左上方下拉菜单统一提供项目切换、创建和“删除当前项目”；侧栏下方不再重复展示项目列表。侧栏在短窗口可滚动访问任务中心。

删除弹窗展示项目名称、完整路径与永久删除范围；点击“确认删除项目”后，完整项目文件夹被永久删除，不移入 `.trash`，不保留恢复备份。项目从列表移除，自动选择下一个项目，最后一个删除后显示创建入口。其他项目和全局模型设置保持不变。

删除沿用工作目录独占锁，检索、聊天和后台工作期间不执行；待启动的下载、转换、索引、综述和一键流程也须结束，暂停下载须先取消。前端向接口传入当前项目 ID 作为确认值，不要求用户输入项目名称。

实现先将目录暂存为同级 `.deleting-<唯一标识>`，随后提交 `config/storage.json` 的删除记录，再移除暂存目录；暂存是事务阶段，不是恢复备份。目录清理前提交失败会原位回滚；清理部分失败会恢复剩余目录和项目登记并明确报错，此时部分文件可能已经删除。读取列表过滤已提交的删除记录，旧请求不能复活已删除 ID。正常自动保存稍后压缩项目列表。

`scripts/test-project-deletion.py` 为隔离目录下的后端验证脚本，覆盖永久删除、其他项目、最后一个项目、旧请求拒绝、锁竞争、路径校验、部分删除失败与提交失败回滚。UI 脚本仍须先检查是否符合当前永久删除交互以及是否使用隔离服务，不能依据历史测试说明宣称已通过。

## 文献库中的文件操作

- **打开项目文件夹**：直接打开 Finder / 资源管理器中的当前项目。
- **打包目前 PDF**：读取 `pubmed/current.xml` 中的 PMID，仅收录对应的现有 PDF 和摘要 MD；同时附当前 XML、清单和缺失 PMID。不会把历史检索中已排除的论文打入包。摘要文件可以独立打包。输出固定为 `packages/current-literature.zip`，校验新包成功后替换旧包，清理应用旧版生成的下载压缩包；失败保留原包。普通打包不会发起网络下载，也不会凭空生成摘要。
- **清空 PDF / 摘要（调试）**：确认后删除当前项目 `pdf/*.pdf`、`abstracts/*.md` 和 `packages/*.zip`，清除文件登记并记录清空事件。同时清除相关活动 Markdown 与向量，记录恢复截止时间，避免旧备份自动撤销清空；冗余 PDF 可按界面选项一并清除。保留 XML、检索式、历史下载报告、笔记、综述及其他项目；不会自动执行。运行中或暂停的下载批次需要先完成或取消。

当前代码只初始化新布局或读取已经迁移的项目，检测到旧 `data/projects` 布局会报错，不再自动迁移，也不生成历史迁移备份。设置中的“迁移项目工作目录”仍可使用；不要手动移动正在使用的数据库。

## 当前集合与冗余文件

当前 XML 移出的 PDF 归档到 `pdf/redundant/`，Markdown 原稿、清洗稿、图片、编辑历史和转换记录校验备份到 `archive/markdown/` 后才删除活动副本；摘要与向量数据清除。重新纳入先恢复 PDF，再恢复兼容 Markdown；不恢复旧索引。显式清空与正常移出采用不同恢复规则，详见 [生命周期](ARTIFACT_LIFECYCLE.md)。

## 阅读对话

`reader/reader.sqlite3` 保存单篇对话与阅读位置，`reader/sources/*.json.gz` 按材料版本共享全文快照；不是每轮复制 PDF 或 Markdown。`notes/notes.json` 保留原有手写笔记。完整项目迁移时需一起保留 `reader/`，细节见 [阅读规范](READING.md)。
