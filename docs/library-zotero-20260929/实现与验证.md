# 文献详情白屏修复与 Zotero 独立导入

## 文献详情

PrimaryMN 下载元数据中，部分 Sci-Hub / Sci-Net 的 `identity` 是结构化对象，包含 `status`、`reason` 和文件指纹。此前 `PdfDetails` 将它直接用作 React 文本节点，点击文献打开详情时会触发渲染异常。

现在类型明确兼容结构化记录和旧版字符串，并把校验原因转为中文说明；未知记录采用文字回退，不直接渲染对象。不修改原始下载元数据。

## Zotero 入口

文献库 → PDF → 更多 → 从 Zotero 导入。针对当前文献库尚无有效 PDF 的条目创建 `downloadMode=zotero` 批次；先复用有效本地文件，然后仅调用现有 `zotero_stage.run`，不执行其他下载来源，也不加载 Bloom。

复用既有 DOI 匹配、附件白名单、文件校验、复制入库和报告机制。仍受项目任务互斥控制，暂停、继续、取消沿用现有任务逻辑；任务中心复用 PDF 条目，失败重试保留 Zotero 模式。

Zotero 未命中不等于完成完整网络下载：失败记录不新建摘要兜底资格，也不把整体 PDF 下载状态标记为最新；已有完整下载记录仍保留原有判定。显式清空 PDF 后，单独 Zotero 导入不会撤销待下载标记。成功导入的有效 PDF 照常进入全文处理链路。

Zotero 必须提供当前已配置的本地 API；本入口不启动 Zotero，不触发同步或在线下载。

## 验证

- Zotero 后端回归 38 项通过，包括独立模式跳过其他来源、复用已有 PDF、失败原因和重试模式保持；使用隔离目录和本机模拟 Zotero 服务。
- PDF 状态与材料依赖回归 20 项通过，包括独立 Zotero 未命中不误报最新、不覆盖既有完整下载结果。
- 实际 Library 组件在 WebKit 和 Chromium 均通过：对象／字符串／缺失／未知身份记录的文献详情正常打开，关闭后可继续操作，阅读器入口正常，菜单仅发送缺失 PDF 的 Zotero 模式请求，无浏览器异常。
- WebKit 任务中心、菜单键盘操作、四档宽度布局，以及批量检索条件和按钮点击范围回归通过。
- TypeScript 检查与 Vite 生产构建通过；保留已有包体积提示。

所有界面 RPC 均使用模拟数据；未对 PrimaryMN 运行实际下载或导入，未修改用户文献。已更新源码及 dist/ui，未重新打包已安装的 macOS 应用。
