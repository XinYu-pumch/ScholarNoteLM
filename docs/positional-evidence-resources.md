# 图表关联证据与仅参考文献清洗

综述材料采用 [单元共享材料包](REVIEW_PROTOCOL.md)：同单元图表统一去重、结构化 JSON 与外置资源、证据 ID 引用校验。本文其余清洗与位置关联原则继续适用。

当前流程：

```text
PDF → 转换原稿 MD → 仅清洗参考文献 → 清洗稿 MD
                                      ├─ 普通分块 → 文本向量
                                      └─ 完整表格 / 图片快照 → 位置关联
检索命中 chunk → 补入关联图表 → 问答 / 综述及证据展示
```

## 内容规则

Marker 转换后固定内置“仅清洗参考文献”，无需选择或启用清洗策略。不删除短段落、标题、列表、图注、表头、作者信息、声明、页眉页脚。参考文献采用既有结构算法，并保留明确 Citation / How to cite 标签后完整本文引用格式的回退，不调用 LLM。原文保留区间不重新生成或排版。历史保守清洗和正文优先实现已移除，原有项目产物与历史报告保留。

取消少于 100 字符不入库的规则。所有非空段落正常分块；长段仍按既有方式二分到最多 8192 个 Unicode 字符。字符数并非 token 数。表格保留在清洗稿和普通文本块中，可能跨多个块；不生成额外重复的图表检索代理。召回时排除少于 100 字符的 heading，保留长 heading、短正文和图注；不会仅因致谢或资助的章节名称删除块。

转换固定使用 Marker。PaddleOCR 的功能、模型和专用环境已删除。

## 位置、存储与版本

- Markdown 解析器识别表格、图片语法、引用式图片及 HTML 表格/图片，代码围栏不作为图表解析。
- 坐标全部来自用于分块的同一份清洗稿：Unicode 字符偏移采用从 0 开始、右端不包含的区间；行号从 1 开始。
- 每个资源与覆盖其原文范围的所有 chunk 关联，同时关联资源前后各两个普通文本段落或标题所覆盖的 chunk。图表内部段落不重复算邻近文本；不使用图表编号、名称、关键词或 LLM 建立关系。
- 位置接近不代表语义相关，模型请求明确要求结合问题与原文判断。
- `vectors/chunks.sqlite3` 的 `resources` 表独立保存完整内容、位置、邻近原文、chunk 索引、PMID 和文档版本；chunk metadata 保存 `resourceIds`，读取证据时补全资源。
- 图片按内容哈希保存到 `vectors/resource-assets/`。只读取当前项目 `markdown/assets/` 下的本地图片，不抓取 MD 中的远程链接。支持 PNG、JPEG、GIF、WebP；缺失或不支持时显示原因并保留邻近文字。
- 新图片快照在 macOS/APFS 上优先以写时复制共享 Markdown 图片底层磁盘块，已有同哈希快照校验后复用，不再次覆写。保留独立文件和旧证据的编辑隔离；不支持克隆时回退完整复制。资源路径、内容哈希、文档版本签名均不改变。
- MD、清洗签名、拆分版本、资源关联规则和图片内容共同参与版本判定。图片改变后新证据使用新版本，旧证据仍读取旧快照。移出文献集合时删除该文献的资源记录及不再共享的图片快照。

“完整表格”指 Markdown 中的一个完整表格对象。转换器已经拆成数个独立表格的跨页表格，程序不推测拼接；Markdown 图片也可能是期刊标识，不凭名称假定它一定是科研 Figure。

## 模型输入与展示

文献问答、综述生成及相应修复请求带上关联资源。单篇全文聊天只发送未清洗 Markdown 或摘要文本，不发送这里的关联图片像素，见 [阅读说明](READING.md)。普通文本向量不包含图片像素。完整表格和邻近文字作为文本证据，模型配置中针对当前模型勾选“支持图片输入”后才发送实际图片。能力选择按模型 ID 保存于供应商配置的 `visionModels`；同一供应商的不同模型可分别设置。

同一次问答请求中的资源按 ID 去重；综述文本资源按写作单元共享池保留，图片在单次请求内去重。最终回答材料不因阅读批容量改成摘录或裁切资源。供应商拒绝图片或上下文超限时显示实际错误；不静默丢弃图片后重试。未勾选视觉时明确告知模型未提供图像输入，不能声称已看过图片。

问答和综述证据面板可展开完整 Markdown / HTML 表格、本地图片及前后邻近原文。文本摘录可以来自 chunk、完整表格或邻近原文，来自资源的摘录保存 resourceId；图片观察不能伪造为逐字摘录。

## 使用与验证

1. 在设置 → Markdown 转换确认 Marker 运行环境已就绪；参考文献清洗自动启用。
2. 在文献库运行“重新清洗”，从 `markdown/raw` 重建清洗稿，无需重新转换 PDF。
3. 建立 / 更新检索索引。新块需要向量，已有相同输入的向量可复用。
4. 对实际支持图片的模型勾选“支持图片输入”并保存，然后重新提问或准备综述材料。

回归覆盖 Markdown 位置解析、SQLite 资源版本、召回补入图表、图片共享与清理，以及问答/综述实际请求和引用修复。`scripts/test-positional-resources-corpus.py` 用于语料检查，执行前核实目标路径；`scripts/test-evidence-resources-ui.mjs` 和 `scripts/test-app-simplification-ui.mjs` 须按 [隔离测试要求](DEVELOPMENT.md#测试入口与隔离) 使用。模拟响应验证协议，不代表实际模型正确理解图片。
