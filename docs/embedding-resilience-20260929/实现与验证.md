# Embedding 自动调度：网络适应与恢复

2026-09-29。已为当前 Embedding 配置启用自动调度：1800 RPM、450000 TPM、请求超时 120 秒、自动索引开启。32 条/批、4 并发保留为手动模式设置。切换调度方式不改变向量模型标识，不会使现有索引失效。

## 行为

- 正常请求从 2 并发起步，根据响应延迟、吞吐和配额调整。运行边界为 1–16 并发、1–32 条/批；批量还受剩余 token 预算约束。
- 在有足够任务且不受配额等待影响的观察窗口中，若延迟上升超过 35%，吞吐增长不足 10%，降低并发并减小批量。不会仅因响应变慢而不断加并发。
- 断连、超时、429、5xx：失败的文本块重新排队，保留已落盘的向量；指数退避带随机抖动，遵循服务的 Retry-After。等待期间任务仍可停止。
- 恢复阶段只发单并发、单文本探测；连续 3 次成功后退出恢复阶段，随后逐步调整吞吐。并行请求中、故障前发出的成功响应不会提前解除恢复状态。
- 所有重试重新申请共享 RPM/TPM 预算；不知道实际用量的失败请求保留原预留，直到滚动窗口过期。问答与索引继续共用限速台账。
- 当前模型使用已校准的 tokenizer 加余量预留；模型、地址或版本不匹配时，自动退回每块 8192 token 的保守预算。实际 usage 超出校准预留时停止并提示重新校准。
- 401/403、模型或参数错误、数量不匹配、无效向量仍明确失败，避免永久错误无限重试。
- 任务中心显示等待网络、等待服务、服务限流、等待额度、恢复探测及写入索引阶段；仍然只保留下载、转换、索引三类任务。

网络恢复指服务能够重新响应，并不保证任何网络都能连通服务或跑满 TPM。长期不可达时继续退避等待，用户可停止；下次启动复用已保存向量。

## 验证

- 39 项后端测试：自适应缓存与去重、共享配额、真实本机 HTTP 故障注入、配置与索引身份、连接验证及输入校验。
- 故障注入连续包含连接中断、请求超时、503、429 和慢响应；恢复后 12/12 块均成功且只落盘一次。逐请求核对配额记录，失败请求也占用预留。
- 真正的子进程 worker + Chroma 集成：通过已保存的自动调度设置启动，验证向量写入、增量复用、材料删除/变更、部分失败重试和日志脱敏。
- WebKit UI：自动调度开关保存、固定参数禁用/恢复、限速字段可编辑；任务中心网络等待/恢复状态、停止操作和原有三条任务布局。
- TypeScript 检查与前端构建通过；保留原有 bundle 大小提示。

本轮故障测试使用隔离的本机服务，没有额外调用付费 Embedding API，也未重新生成 PrimaryMN 的已有向量。此前真实服务吞吐数据不等同于本轮网络故障测试，保留在 `docs/embedding-throughput-20260929/`。
