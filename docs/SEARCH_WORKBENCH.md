# 检索工作台与检索助手

首次实现：2026-09-19；操作说明更新：2026-09-28。React / TypeScript 界面，Tauri 2 原生命令，Rust 研究服务，SQLite 状态与全文检索。没有新增全局 Python 环境。PDF 下载、Marker 转换、向量化、文献问答与综述写作现已通过独立服务接入。

## v0.3.1 显示修正

- 每条建议显示完整 PubMed 检索式，支持独立复制与加入管理；兼容旧版将正文和检索式分开保存的消息。复制整条回答也会包含原先仅存于结构化字段中的检索式。
- 推理区提供明确的「展开 / 收起」按钮，流式 token 更新不重置手动操作，生成结束仍自动收起。旧记录未保存推理时不会补造推理；旧版长说明归入独立的「策略说明」折叠区。
- 所有下拉选择（设置、检索式、文献库、阅读器、问答范围）使用统一自绘菜单，白色/深绿色面板与浅绿选中态，不调用 macOS 灰色原生选择器。支持方向键、Home/End、Enter、Esc 与输入前缀定位；弹窗内菜单置于弹窗层中。
- 模型配置按「服务连接 / 模型与生成」分组，限制面板与输入框宽度。PubMed 可选配置单独折叠；窄窗口使用纵向布局。

## 使用顺序

1. 打开「设置 → 模型与服务」，填写兼容 Chat Completions 的 Base URL、模型与可选密钥。可获取模型列表、测试连接、保存多个配置。保存并启用的配置用于检索助手。
2. 「设置 → JCR 参考文件」默认使用复制到本项目的 BADR `2025JCR.xlsx`。新表格只有通过校验才启用。
3. 「设置 → MeSH 本地索引」查看本地词库。已经从官方生产版建立 2026 索引，包括主题词、限定词和 SCR。
4. 进入项目的「检索工作台」，点击「＋ 添加检索式」直接增加一行。填写标题和检索式，行内选择排序与数量；双击条目可编辑完整检索式、日期和 JCR。新条目默认相关性、30 条，不限日期和 JCR。
5. 行内修改后点 ✓ 保存，或点 ▶ 保存并执行。也可在「检索助手」讨论需求，把建议加入管理页，再明确执行；助手不会自动查询 PubMed 命中数。
6. 执行完成后自动按 PMID 去重，更新「合并结果」及文献库。总 XML、单次执行 XML 均可导出。

## 已实现的边界

- PubMed ESearch / EFetch 真实网络调用，统一速率限制、超时和有限重试；只读取记录自己的 PMID、DOI、PMCID，避免误取参考文献标识。
- 发表日期使用 `datetype=pdat`；相关性属于排序，不是质量过滤。
- 探索模式先获取相关性或发表日期排序的候选 PMID，再按每批 100 条读取 XML，直到得到目标数量的有摘要、符合 JCR 条件的文献，或候选耗尽。候选上限统一为 **9,999 条**（PubMed 当前会将请求的 10,000 条截为 9,999 条）；目标数量与候选上限分开处理。达到候选上限但仍未查尽全部命中时，明确标记“已达候选获取上限”。已有成功候选快照仍可复用。
- 完整收集对超过 9,999 条的结果按发表日期递归分区并核对去重数量，包括恰好命中 10,000 条的情况。单日超过限制或分区计数不一致时返回错误，不宣称已完整收集。PMID 缺失、重复或格式异常仍报错并保留旧结果，不能把不完整响应当作正常限量结果。
- 检索式保存草稿与正式执行分离。执行成功且修订号未变化才切换当前执行版本；失败保留原结果。成功的零命中会替换原结果。
- 归档/停用检索式只移除当前来源贡献；其他检索式仍命中的 PMID 保留。历史 XML、快照、原型笔记与移出文献缓存保留。
- 所有筛选条件属于单条检索式。修改检索式、日期、数量、排序后仅该条标记待更新，仍保留旧 XML，重新执行成功后替换。JCR 是取得 XML 后的本地筛选，保存后立即重筛该来源。批量执行只使用已保存且非空的启用策略，按条提交。
- XML 导入作为独立固定批次，原始检索式标记未知；要求 PubmedArticleSet / PubmedArticle 及有效 PMID。PubmedBookArticle（书籍章节）与期刊文章同样按主体 PMID 解析；网络 EFetch 缺少任何请求 PMID 都阻止提交。
- 总 XML 是数据库的派生输出，不能通过直接删除磁盘上的 XML 文件改变文献集合。请在工作台归档检索式。
- 检索助手使用一次流式模型请求，输出可读的策略说明和 PubMed 代码块；完成后提取可添加的检索式，并在本地核验 MeSH 名称。不做 PubMed 试检索，不生成命中数；未核验 MeSH 会显示提示。需要点击「加入检索式」才建立草稿。
- PubMed 有时会静默忽略未知字段。程序额外检查常见官方字段名称/别名、括号与引号；保留实际 QueryTranslation 与警告供查看。核验成功不等于检索策略已查全。
- 模型高级参数只保留温度和等待新数据超时；温度留空不发送该字段。不发送 max_tokens 或 max_completion_tokens，旧配置中的输出上限也不会参与请求。支持兼容 Chat Completions 的 SSE；原生 Anthropic / Gemini 专有协议尚未实现。

检索工作台不再提供独立的 MeSH 查词按钮，词库更新仍在设置中，检索式的本地 MeSH 核验继续保留。文献来源工具栏不再显示 PubMed/Zotero 纳入规则提示，实际筛选行为不变。工具栏在文献来源标签内左对齐，依次提供更新检索、添加检索式、导入自 Zotero、批量筛选、导出 XML；全部重新检索与归档视图移入更多菜单。导出 XML 不在检索助手或公共页头展示。

## 对话、分支与快捷键

- 左侧「我的对话」按项目隔离；＋ 新建独立对话，标题旁铅笔可重命名，点击列表切换。旧版本的项目聊天自动迁移为「之前的对话」。
- 用户消息可「编辑重发」，助手消息可「复制」与「重新生成」。编辑重发/重新生成都会创建新分支，保留原对话及之后的消息；新分支携带分叉点之前的上下文。
- 每条消息提供「从这里开启新对话」，复制到该消息为止的上下文，随后可继续输入。分支用编号与来源名称区分。
- Enter 换行；macOS ⌘ + Enter、Windows Ctrl + Enter 发送；输入法组合输入期间不会触发发送。
- 输入框固定在聊天区底部，仅消息区滚动；用户向上阅读时不会强行滚回底部。用户消息使用浅绿底色，助手使用浅灰底色；深色主题同步适配。
- SSE 到达即显示正文和服务商实际返回的推理内容；兼容 reasoning_content、reasoning、可见 reasoning_details.text 与 content 中的 `<think>` 标记。不生成或虚构推理内容。推理在输出时展开，完成或停止后自动折叠，可手动展开查看。
- 测试连接收到正文或推理即成功；请求超时按等待响应/新数据计算，持续输出推理不会因总时长超过该值而失败。支持停止生成，已接收内容保存；截断、超时或服务错误保留部分回答与错误提示。
- 切离检索助手页面不会取消生成；不同对话可同时运行，“停止生成”仅作用于当前对话。刷新、重启后恢复已保存的消息，不等于自动恢复中断请求。
- 右键对话或点击条目的管理按钮，可重命名、复制、删除；“选择对话”支持全选和批量删除。
- 顶部“对话目录”按提问编号，支持搜索、跳转和回到最新；侧栏可收起，长标题不撑宽列表。

## 条目筛选与迁移

旧的项目筛选条件只在迁移时复制给已有检索式；新建检索式始终使用 30 条 / 相关性 / 日期为空 / JCR 为空。已存储的 XML、执行历史、模型密钥和 MeSH 索引不删除。

同一 PMID 命中多个检索式时，只要至少一个启用来源通过自己的 JCR 条件，该 PMID 就会进入合并集合。来源信息保留每条策略的通过状态；因此归档一条来源不会错误删除另一个来源仍纳入的文献。JCR 参考文件更新后，所有启用 JCR 的来源使用新表重筛。

当前界面使用「前 N 条」收集；为兼容历史数据，后端保留完整收集模式，历史全量策略在未修改数量时维持原模式。

## JCR 校验和筛选

读取 .xls / .xlsx 第一个工作表。必需列与 BADR 一致：

`Journal, ISSN, eISSN, Category, Total citation, JIF, Quartile, JIF rank`

必须有数据，Journal 非空；非空分区只能为 Q1–Q4，忽略大小写和首尾空格。与 BADR 的 pandas 读取行为一致，将 N/A 等缺失标记视为空值，作为警告报告，而非误认成非法分区。

默认表包含 **22,249 条记录、2,303 条缺失分区记录**。缺失分区与无法匹配期刊都由“保留并标记 / 排除并记录原因”策略处理。

ISSN/eISSN/ISSNLinking 优先匹配，期刊规范化名称用于无歧义回退。保留同一期刊全部类别，任一类别满足所选分区即可纳入。参考文件以 SHA-256 标识版本，原始文件及标准化记录留在项目内。上传失败绝不激活新版本。

## MeSH 索引与自动更新

官方来源：

- https://www.nlm.nih.gov/databases/download/mesh.html
- https://nlmpubs.nlm.nih.gov/projects/mesh/MESH_FILES/xmlmesh/

不通过大量逐词 API 请求抓取全库，使用官方压缩 XML 批量源。首次构建已包含：

| 类型 | 数量 |
|---|---:|
| Descriptor 主题词 | 31,110 |
| Qualifier 限定词 | 76 |
| Supplemental Concept 补充概念 | 324,046 |
| 合计 | 355,232 |
| Term 表达（含规范词、入口同义词） | 996,332 |

索引保存规范名称、唯一 ID、同义词、范围说明、分类树、允许的限定词及补充概念映射。SQLite FTS5 提供本地全文查词。词库年份与应用解析格式版本分开管理。

自动更新默认开启：应用运行期间每小时检查是否到期，7 天到期后访问官方目录，发现新生产年或文件 ETag / Last-Modified 变化时更新。失败至少间隔 6 小时重试。应用关闭时不安装系统常驻任务，下次启动补检查。设置中可手动检查、关闭自动更新、决定是否包含 SCR。

每次使用新的版本目录构建，验证下载长度、记录 SHA-256、解析结束、主词条数量和 SQLite 完整性，全部成功后才切换数据库内的活动指针。原索引持续可读，失败或应用退出不破坏旧版本。同版本字节已核对的官方源可以复用。

## 数据位置

所有路径相对 ScholarNoteLM 根目录：

| 内容 | 位置 |
|---|---|
| 模型服务配置等全局设置 | `data/research/research.sqlite3` |
| 本项目检索式、执行记录、来源关联、集合版本、助手对话 | `<工作目录>/<项目>/metadata/research.sqlite3` |
| JCR 默认文件与内容版本 | `data/reference/jcr/` |
| MeSH 原始压缩文件、清单与 SQLite FTS5 索引 | `data/reference/mesh/<版本>/` |
| 每次检索的原始响应与合并原文 | `<工作目录>/<项目>/pubmed/queries/` |
| 不可变集合快照及清单 | `<工作目录>/<项目>/pubmed/snapshots/` |
| 当前集合 XML（可重建输出） | `<工作目录>/<项目>/pubmed/current.xml` |
| 导出的 XML | `<工作目录>/<项目>/pubmed/exports/` |
| 项目列表、当前项目、主题等界面状态 | `data/prototype/state.json`（文件名沿用早期命名，内容是现行状态） |

模型密钥保存在研究数据库中；常规设置响应只返回“是否已保存”，不返回密钥。macOS/Linux 下研究目录权限为当前用户独占。数据库未做应用层加密，请将含凭据的数据库视作个人配置，勿分享。项目 `.gitignore` 已排除 `data/`、`config/` 和 `workspace/`。没有读取或复制 BADR 的模型凭据。

浏览器开发模式通过同一 Rust 引擎 CLI 调用研究功能，聊天使用 NDJSON 实时转发；正式桌面通过 Tauri IPC Channel 接收流式事件并直接调用后台命令，不依赖 Vite 或另一个 HTTP 服务。开发桥限制同源 JSON 请求，避免浏览器其他页面调用本地配置接口。

集成与界面测试使用项目 tmp/ 中的独立研究数据库，界面测试隔离原型存储，不覆盖用户项目。测试用模型服务只验证协议和流程；实际模型生成质量需要用户配置自己的服务后评估。当前仅验证 macOS Apple Silicon，Windows 源码保留兼容，尚未构建或运行验证。

## XML 快照存储

新查询、导入和合并集合将原始 XML 按字节哈希无损压缩到项目内 `pubmed/objects/<hash>.xml.gz`，清单的 `xmlPath` 指向共享对象。来源、筛选及执行历史各自保留；相同内容复用，不同内容独立压缩。合并快照的存储路径不参与原有集合签名。当前 `pubmed/current.xml` 和显式 XML 导出仍是普通 XML；历史明文快照兼容读取，压缩内容读取时校验哈希。


### 双语行为

检索助手每个对话保存回答语言，新对话采用设置默认值。中英文提示词均保持 PubMed 语法及英文医学检索词；语言只改变讨论与说明。后续提问采用当前对话语言，重新生成沿用原消息语言，分支继承分支点。界面切换不改写历史。
