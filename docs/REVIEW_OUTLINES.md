# 综述工作区：大纲与正文

综述工作台以独立工作区管理综述，工作区内部通过「综述大纲 / 综述撰写」标签切换。每个工作区只有一份当前大纲，无需管理版本；标题深度仍不限。

## 工作台布局与操作

- 左侧为可搜索、可收起的工作区列表，显示材料实际模型与最近任务状态；底部依次为新建和删除当前工作区（删除需确认）。窄窗口使用抽屉。切换工作区不会停止任务，重新进入从磁盘恢复进度。右击列表条目或按 Shift+F10 打开名称与描述编辑、创建另一语言综述的菜单，操作针对该条目。右侧不重复工作区名称；顶栏依次显示分栏按钮、单行综述语言选择、主题。打开文件夹入口仅保留在撰写结果工具栏。
- 已有大纲默认折叠生成设置；没有大纲或正在生成时展开。浏览大纲可折叠任意层级，进入编辑后显示全部节点；CSV、导出、恢复原始大纲位于更多菜单。
- 主操作固定为「准备写作材料」「撰写综述」「撰写设置」「更多」。准备与撰写各自显示初始、运行、停止中、重试失败项和完成状态；运行按钮悬停/键盘聚焦显示停止，触屏直接显示停止。准备完成按钮禁用，只有全部材料通过文件和资源校验后才允许撰写。更多菜单提供新一轮、全部重写、历史草稿、任务记录与重置；结果工具栏保留目录、全文预览、导出菜单、完整稿件和文件夹。全文预览再次点击返回当前章节；导出统一名为「导出」，输出当前结果，完整与不完整内容都可导出。撰写设置中模型单列，并发数与每节参考片段数并排；材料长度限制、额外要求等默认折叠在高级设置中。
- 大纲/生成要求取消编辑、切换工作区或页面，以及撰写设置的取消/X/Escape/遮罩关闭，统一先处理未保存草稿：继续编辑、不保存并离开、保存并离开。写入失败保留原输入，保存成功才继续原操作；保存过程中阻止重复离开。撰写参数保存后仍按原签名规则判断正文是否需要更新。此保护不等同于 Tauri 原生窗口关闭保护。
- 撰写目录可折叠、收起；分隔条支持拖动或方向键调宽。进入时恢复本次会话选中的章节，首次选择已有正文的章节；纯组织标题显示可跳转的直接子章节。
- 正文、目录、证据各自滚动。证据默认关闭，正文引文按 PMID 展开当前小节/共享材料池中的对应片段；全文预览保留原有引用文献弹窗。窄窗口证据以抽屉显示，关闭按钮、遮罩和 Escape 均可收起。
- 材料进度按终末标题累计；正文进度按实际需要生成的节点累计（包括导语、不包括纯组织标题）。重试从已校验的 80/105 继续，失败或取消不计入完成；页面两条累计进度字号和进度条规格一致，不再显示重复的模型摘要和任务组统计，原始记录仍可通过更多菜单中的任务记录查看。空召回视为失败，不足 topK 明示但不重复填数。

## 大纲

- 工作区名称为 1–64 个中文、英文字母、数字或下划线，不区分大小写，不接受 Windows 保留名。描述可以中文填写。
- 沿用 BADR 大纲提示词，向当前启用的 LLM 发送主题、额外要求和当前 XML 中所有可用标题、摘要。
- 完整提示词可单独导出；生成支持取消、推理活动计数及严格 CSV 校验。
- CSV 为 `Serial,Title` 两列，父节点先于子节点，同级从 1 连续编号；最多 1000 个标题，不限制深度。
- 支持编辑、增加、移动、删除标题分支。内部稳定节点 ID 独立于显示编号，避免插入或重排标题后正文错位。
- 重新生成成功才替换当前大纲，失败或取消保留已有大纲。“恢复默认”恢复本工作区最初的 `generated.csv`。
- 旧版 schema-1 工作区已全部迁移，当前代码遇到未迁移的旧格式会直接报错；不提供版本管理入口。

## 检索与两步撰写（2026-09-28 更新）

1. 完整树确定终末标题，中文原文直接用于 query，不翻译、不拼接父标题。
2. 复用现有段落分块，全文优先；没有 PDF 的文章使用 PubMed 摘要，有 PDF 但 Markdown 尚未就绪的文章等待转换。参考文献在 Markdown 清洗阶段移除；召回排除少于 100 字符的 heading，保留长 heading、短正文和图注。
3. 召回使用已保存且验证成功的 Embedding API（例如 BGE-M3），按余弦相似度排序。复用 `vectors/chunks.sqlite3` 中同模型、同输入的已有向量，只请求缺失向量与 query。不提供重排。
4. Embedding 只接收 chunk 原文，不拼接论文标题或章节路径。完整表格、图片及邻近文字按位置关联补入材料池，按 ID 去重。
5. 每个终末标题直接召回撰写页设置的 topK 块，不设置额外候选池；不足时不重复填数。
6. 按 BADR 混合深度规则分配写作单元：同一父节点的直接子标题全部为终末节点时合并；混合深度的独立终末节点单独处理。所有叶节点只分配一次。

### 第一步：准备综述提示词

- 只做召回、关联图表收集与提示词装配；不调用撰写 LLM，也不要求先配置撰写模型。
- 每个写作单元保存 `review_parts/prompt_section_<标题编号>.json` 共享材料包；TXT 仅作阅读预览，图表保存在 `review_parts/resources/`。
- 每个终末标题独立检索，在单元内按 chunk ID 和资源 ID 去重；所有终末标题共享证据池。检索来源、排名、文献版本和位置明确记录，来源关系不限制其他子标题使用。
- 单次请求字符预算默认关闭。主动开启后，超预算要求提高或关闭预算，保持联合撰写，不自动拆分或截断材料。
- `prompts/<稳定节点ID>.json` 保存证据、文件清单、校验值和输入指纹。重复点击复用最新结果，取消后可继续。

### 第二步：生成综述

- 检查所有所需提示词是否已准备且最新；从 JSON 材料包读取并校验结构和外置资源指纹，发送前补入完整内容。不再次召回或加载重排模型。
- 默认 LLM 并发 3，允许任意正整数，不设置人工上限；实际活跃请求不超过待生成写作单元数。每个终末标题默认最多 7 块证据。
- 返回 JSON 按大纲编号和标题校验，并映射回内部稳定节点 ID；检查缺失、重复、越界和引用范围。父标题引导段不分配独立 PMID 引用。输出使用证据 ID，经程序校验后转换为 PMID；结构或引用失败时用同一共享池联合修复一次，仍失败不发布。
- 保存 `review_parts/section_<标题编号>.json`，含去重证据池、图表池、检索来源，以及各节点原始证据 ID 引用和转换后的 PMID 正文。详见 [共享写作材料包](review-shared-pool.md)。
- 每轮在 `writing-round.json` 冻结材料模型、源文献签名与检索参数。完整材料独立于当前项目索引：切换 Embedding 模型、删除向量库后仍可用原材料撰写，界面显示原材料模型与当前项目模型。未完成轮次只能在同一文献与模型下继续，否则需要明确准备新一轮，不能混入另一模型结果。
- 更改大纲或材料参数须重新准备；更换正文 LLM 不重复召回，正文会显示待更新。仅修改并发、密钥或限速不使完整材料过期。正式 JSON、外置资源缺失或被改动时要求重新准备；编辑 TXT 预览不改变实际请求。
- 正文始终按完整大纲顺序装配，不按异步完成顺序拼接。取消或失败保留已完成正文，旧正文显示其当时的证据。
- 两步均支持取消和继续；进行期间禁止 app 修改大纲。材料准备期间源文献变化时不发布受影响结果；正文使用冻结材料，不重新读取当前项目原文。发送和发布前再次校验材料文件与资源。

## API 配置、验证和限速

- 设置 → Embedding 模型：配置服务地址、模型、密钥，发送一次真实请求验证非空、有限、维度一致的向量。成功验证绑定地址/模型/版本/密钥；改动这些字段需要重新验证。测试草稿不会代替保存配置。
- 设置 → Embedding 模型 → 高级请求参数：设置 RPM / TPM；在同页启用已验证的配置。索引和查询使用当前项目绑定的模型；全局默认只影响新项目。配置保存不自动改变已有项目的模型身份，需点“将此配置用于当前项目”。密钥与限速继续读取对应服务商配置。
- 查询和批量文献向量化共享跨进程限速数据库，按服务/模型/凭据隔离。默认 60 RPM / 120000 估算 TPM 是应用保守值，不代表账号配额。输入 UTF-8 字节数加少量开销作为保守估计，响应有 usage 时按实际用量修正。
- 保持完整文本，将批次按估算预算拆成多个请求，不改变文本块。429 遵循 Retry-After，并指数退避；其他服务端临时错误和网络故障有限重试。等待与 HTTP 请求可取消。
- BADR 的对应实现按批次串行请求；这里补充跨任务共享限速。硅基流动 Embedding 同时受 RPM、TPM 约束，具体模型/账号配额以控制台为准：[官方限速说明](https://api-docs.siliconflow.cn/docs/userguide/faqs/rate-limit-and-upgradation)。
- BGE-M3 输入上限是 8192 tokens，不能把字符数当 token 数；超限明确报错，不请求自动截断：[官方 Embedding 接口](https://api-docs.siliconflow.cn/docs/api/embeddings-post)。

引用范围校验不保证每个论断都被材料充分支持，研究者仍需核对。

## 文件与导出

```text
项目/review/GutReview2026/
  review.json                 # 工作区描述与迁移信息
  outline-state.json          # 主题、要求、生成状态与编辑修订号
  outline.csv                 # 当前完整大纲
  generated.csv               # 最初生成的大纲，用于恢复
  nodes.json                  # 稳定节点 ID
  source.xml / abstracts.txt  # 大纲生成的摘要来源
  prompt.txt / prompt.json    # 大纲完整提示词
  response.txt                # 大纲原始响应
  writing-settings.json       # 正文参数
  writing-round.json          # 本轮大纲、模型与文献快照
  writing-job.json            # 单次请求任务进度
  retrieval/                  # 原始标题 query 与各终末标题的选中文本块
  prompts/                    # 提示词文件清单、校验值、准备状态
  review_parts/               # prompt_section_*.json、TXT 预览、resources 与 section_*.json
  sections/                   # 写作单元正文、证据、输入指纹
  manuscripts/<稿件ID>/document.json # 已保存的完整稿/草稿，保留原稿件内容哈希
  manuscripts/assets/         # 稿件间共享、按内容哈希命名的压缩图片
  logs/<任务ID>/              # 冻结输入、完整提示词、模型响应、修复记录、日志
  exports/                    # Markdown、Word、HTML
```

导出沿用 BADR 的完整大纲装配。HTML 采用目录、正文、引用详情三栏，支持 Markdown 排版，点击 PMID 显示该小节素材和 PubMed 链接；同一单元的终末小节可查看整个共享池中该 PMID 的素材和关联图表，其他单元的材料不混入。Word 使用 python-docx，封面标题与生成时间、分页、层级标题、粗斜体、列表和表格；参考文献仅使用实际引用的 PMID 与 PubMed 链接。HTML 与 Word 读取同一份规范化章节。未完成内容导出时明确标记为草稿，导出草稿不会自动归档为完整稿件。删除工作区是永久删除，确认框说明保留范围。

“已保存稿件”只列出所有写作节点齐全且经过校验的完整稿件，生成完成后自动按内容哈希去重保存。部分正文保留在当前工作区以供重试；重置或新一轮前，完整稿进入稿件列表，部分稿进入“历史草稿”。历史草稿含旧版已归档的不完整稿件，支持独立查看与导出，不计入完整稿件数量。

已保存稿件按 `manuscript-shared-images-v1` 组织内部存储，将重复 data URL 变成共享图片引用；图片使用无损 gzip 保存原始 data URL，以 SHA-256 校验。读取时还原完整稿件，再按既有内容哈希校验，所以稿件 ID、引用、模型输入签名均不改变。旧版单文件稿件兼容读取；再次保存相同稿件时转换存储表示，也可用 `scripts/compact-project-storage.py --apply` 批量无损迁移。该命令默认只读估算。

资源池属于 `manuscripts/`，不依赖当前 Markdown、向量、写作材料包或大纲；重置当前撰写仍能查看和导出旧稿。移动内部归档需要整个 `manuscripts/` 目录。HTML 导出始终将图片及其他资源完整内嵌，可只移动一个 HTML 离线查看。

HTML 使用 `offline-evidence-pool-v1` 内嵌资源表：图片按内容去重，正文及引用详情复用；同内容的完整资源和证据片段也只保存一份，章节/PMID 保留独立列表及顺序。每处正文引文、资源编号与显示位置保持不变，不按 PMID 合并不同原文。浏览器只从本文件读取图片，不依赖项目内的 `manuscripts/assets/`，不改变图片字节或画质。

已有 HTML 默认不改动；`scripts/compact-project-storage.py --html` 只读估算，加 `--apply` 才迁移。迁移核对资源哈希、完整证据还原及正文图片还原，保留正文、样式和原导出时间，不重新撰写或从当前大纲重新导出；无法识别的早期原型/自定义阅读器跳过。新格式迁移可重复执行。

## BADR 格式对齐验证

使用用户提供的 `zmj0606/review_parts_cn/section_1.json` 作为样例生成 HTML 和 Word，完成浏览器 PMID 点击验证及 Word → PDF 排版检查。自动化测试覆盖面向用户的 JSON 精简结构、数字章节编号、严格节点/标题校验、引用作用域、HTML 安全转义、Word 层级/样式/链接以及完整的两阶段流程。

提示词格式版本改变会将旧提示词标记为待更新；再次准备会复用仍匹配的检索缓存。既有正文与文件保留，不在升级时自动覆盖用户结果。BADR 原实现将单块素材截到 3000 字符；这里保留当前完整素材与字符预算检查，避免无提示丢失证据。

## 请求日志存储

新任务的冻结输入 `input.json.gz`、请求 `*.prompt.json.gz`、返回 `*.response.txt.gz` 使用无损 gzip，问答推理日志同样压缩。直接在生成时生效，不需要维护脚本；重试、读取与历史稿件上下文兼容旧明文记录。任务状态、检查点、正文和模型协议不变，正在追加的 worker 日志保持普通文本。


### 双语行为

综述工作区的内容语言统一控制大纲提示词、正文提示词及导出阅读控件。没有大纲时可以选择中文或英文；已有大纲后，通过“创建另一语言的综述”复用主题和额外要求，原大纲及正文保留。项目材料和索引共享。新协议显式写入 promptVersion；旧缓存不因界面语言改变而失效。
