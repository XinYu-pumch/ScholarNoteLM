# 文件生命周期与“最新”状态

文献库按 **当前 XML → PDF → Markdown → 向量索引** 显示处理状态。只处理当前 XML 中的 PMID；同一篇仍被其他有效检索式命中时不会移除。

## 文献移出与重新纳入

1. 移出当前 XML：PDF 移到 `pdf/redundant/PMID.pdf`。
2. 删除对应摘要、Markdown 原稿和清洗稿、图片、转换登记、JSONL、源文本快照、全部历史文本块及向量索引登记。不为这些派生数据建立备份。
3. 从所有 Embedding 模型对应的 Chroma 集合删除该文献，清理不再被其他文献使用的向量缓存。Chroma 正在写入时，物理删除排队执行；文献立即退出检索范围，界面显示剩余清理数量。
4. 重新纳入 XML：优先校验并恢复冗余 PDF。Markdown 和索引重新生成，该文献不会直接复用移出前的向量缓存。

生命周期编号防止运行中的旧转换或索引任务写回过时结果。删除与清理任务持久化，意外中断后可重试。旧 XML 快照、下载日志及历史检索记录保留，历史记录不参与当前检索与恢复。

有效空 XML 表示集合为空；XML 缺失、解析失败时不会推断“全部移除”。旧版冗余 Markdown 目录也会清理，避免重新纳入时恢复旧派生文件。

## 如何判断“最新”

| 阶段 | 最新条件 | 上游变化后的行为 |
|---|---|---|
| XML | 当前合并 XML 已读取，显示内容指纹 | 按 PMID 重新核对成员 |
| PDF | 当前 PMID 有通过校验的 PDF | 新增文献先恢复冗余 PDF，再下载缺失项 |
| Markdown | PDF 内容指纹、生命周期、原稿及清洗规则与转换记录一致，清洗稿存在 | PDF 改变时重新转换；仅清洗规则或原稿改变时重新清洗 |
| 向量索引 | 当前模型配置、文本版本、拆分规则及实际 Embedding 输入与已发布索引一致 | 显示待更新，只重新处理变化的输入 |

内容指纹使用 SHA-256；文件时间、大小用于避免重复读取，不能单独决定内容是否相同。仅修改时间、XML 条目重排，或新增无关文献，不会要求其他文献重新做 PDF/Markdown。标题、正文、章节等实际输入发生变化时会更新相关索引。

手动编辑清洗后的 Markdown 可保留该编辑：Markdown 相对 PDF 仍有效，但索引变为待更新。手动编辑原稿则提示重新清洗。worker 数量改变不要求重做已有结果。

已有 PDF 但 Markdown 过期时，索引显示等待全文转换，不将旧全文当作最新；没有 PDF 时可使用 PubMed 摘要建立索引，列表明确标为“摘要索引”，PDF 仍显示缺失。仅摘要索引完成不表示全文流程完成。

全部阶段完成且上游未改变时，文献库显示“最新 · 无需更新”；相应更新按钮停用，避免重复启动任务。文本块浏览、打开文件等操作仍可使用。

## 本次拆分规则变更

先按空行分段；超过 8192 字符的段落，选择最接近中点的英文句号 `.` 二分，仍超长则继续二分。没有合适句号时按字符中点拆分，避免单块无限增长；小数点不作为优先句界。不足 100 字符的段落继续按既有规则忽略。

拆分版本变化会让既有索引显示“待更新”，不影响 PDF 和 Markdown 的最新状态。点击更新索引后复用仍匹配的输入，仅对变化的文本块请求 Embedding。
