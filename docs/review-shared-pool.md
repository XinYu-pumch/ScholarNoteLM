# 综述联合写作与共享材料包

> 本页记录 v1 共享池设计。当前 v3 延续共享与联合写作机制，输出使用正文块、资源块和结构表格块，并统一图表编号与交叉引用。当前协议详见 [正文图表与引用展示](review-resource-blocks.md)。

协议：`review-unit-shared-pool-v1`。保留现有大纲分组：同一父标题下的终末子标题一起撰写，各子标题继续独立 query、独立召回 topK，再在本单元内合并去重。不把同一篇论文的不同 chunk 合并，不做语义摘要或模糊去重，不将多个写作单元的证据混在一起。

## 文件与模型请求

```text
review_parts/
  prompt_section_1.json       # 正式输入，包含单元、子标题、共享池和输出契约
  prompt_section_1.txt        # 程序生成的阅读预览，编辑它不改变实际请求
  resources/<sha256>.md       # 原文表格或图片原文标记
  resources/<sha256>.html     # 原文 HTML 表格
  resources/<sha256>.png      # 图片快照，也可为 jpeg/gif/webp
  section_1.json              # 已校验的联合写作结果
```

材料包顶层字段固定为 `schemaVersion`、`unit`、`task`、`retrieval`、`evidencePool`、`resources`、`outputContract`。

| 字段 | 内容 |
|---|---|
| unit | 写作单元、需返回的节点、父级与同级大纲背景；节点区分终末正文和导语 |
| task | 主题、语言、已有额外写作要求 |
| retrieval | 每个子标题的 query、召回证据 ID、原排名与已有评分 |
| evidencePool | 单元内按稳定 chunk ID 去重的原文，局部编号 E1、E2…；保存 PMID、来源类型、文档版本、位置、resourceIds、retrievedFor |
| resources | 单元内按稳定资源 ID 去重，局部编号 R1、R2…；保留内容文件及指纹、双向关联、资源前/后原文及其位置 |
| outputContract | 必须返回的 unit_id、完整节点编号和标题，以及 markdown 字段 |

引用来源与使用权限分开：`retrievedFor` 表示哪些子标题找到了这个文本块；同单元内所有终末子标题都可以使用池内相关证据，包括兄弟标题召回的材料。导语仍不引用。

发送前，程序核对正式 JSON 的哈希、字段和引用关系、外置文件的路径和 SHA-256；读取并补入完整表格，给当前明确勾选支持图片输入的模型补入实际图片。文件路径不要求模型自行读取。未提供图片时明确标注模型只能使用文字。表格内换行、引号、Markdown 标记等作为 JSON 字符串数据，不用于划分小节边界。

同一个资源在一次请求中只有一份；源 MD 已经拆成多个对象的表格仍分别保留，不猜测拼接。图片与表格继续由原文位置关联，不识别图表名称。所有原始内容保持，不使用 LLM 预处理。

## 输出与程序校验

模型输出保持 Markdown 正文，包括可能生成的 Markdown 表格，但引用使用本次材料池中的 `[E1]` 或 `[R1]`，不自行填写 PMID。输出 JSON 只接受规定的 `unit_id`、`sections`，各节只包含 `node_id`、`title`、`markdown`。缺失、重复、额外节点及错误标题被拒绝。

程序检查引用 ID 是否属于当前共享池、是否位于允许引用的终末节点，以及引用格式是否有效，再确定性地转换为 `(PMID: ...)`。同一 PMID 可以对应多条证据，不按 PMID 去重正文。结果同时保存：

- `sourceMarkdown`：模型输出的证据 ID 引用正文。
- `markdown`：已转换为 PMID 的展示正文。
- `citationRefs`：证据 / 资源 ID、真实 chunk / 资源 ID 与 PMID 的映射。
- `citationPoolVersion`：所用协议版本。

结构或引用失败时，最多进行一次针对整份联合输出的修复请求，继续使用同一个共享池和所有相关图片；仍失败则不发布。网络故障不因此无限重试。原始响应、实际模型请求与修复请求保存于任务日志。

这些校验确认结构、归属及可追溯性，不证明每个论断被证据支持，也不保证不同小节完全没有重复表述。父标题、正文排序和组装由程序确定，不依据模型返回顺序。

## 预算、界面与导出

字符预算默认关闭。主动开启后超预算会要求提高或关闭预算，不再自动拆成独立子标题请求，不截断材料。联合写作的内容协调目的始终保留。

app 证据面板展示单元共享池、局部证据 ID 和检索来源小节；图表在共享面板中去重展示。正文预览支持 GFM 表格。

导出 HTML 的引用详情可读取同单元共享材料、完整表格和内嵌图片。Markdown 源码作为数据安全渲染；HTML 表格只保留单元格文字、行列跨度等限定结构。旧字符串证据导出仍兼容。正文中的表格引用同样成为可点击 PMID。独立 HTML 无需联网加载图片。

## 旧项目与验证

旧 TXT 输入不会被误当成新材料包；升级后需再次“准备综述提示词”。仍匹配的逐子标题检索缓存可以复用。旧生成正文继续可查看、导出，并标记待更新；不自动覆盖。正式 JSON 或任何资源变动后，材料包失效。TXT 仅是预览，其修改不影响正式输入。

本次使用 HUSandgene/review2 的 23 个已有检索快照进行隔离重打包：105 个 query、735 次召回，在各单元内去重为 678 个 chunk；关联资源在各单元内共 135 个，其中 63 次图片输入。所有原始 chunk 和完整图表保留，46 个项目输入/提示词文件未修改，没有调用真实 Embedding 或 LLM。当时的样本材料包和报告已随 `experiments/` 归档到 `backups/history-20261002.tar.gz`。

验证覆盖共享引用、跨单元/导语越界拒绝、节点结构校验、资源篡改和路径拒绝、视觉开关、联合修复、检索与写作分阶段、并发/取消/恢复、旧正文兼容、Markdown 表格和导出资源。真实 Rust RPC 与独立 worker 使用隔离临时项目及本地 HTTP 模拟服务；没有发送用户文献到在线模型。

最终验证：60 项综述后端测试通过；真实 RPC/worker 集成测试通过；共享证据与离线 HTML 界面测试通过；TypeScript/Vite 构建通过。另验证生成过程中正式材料包被修改时，模型响应不会发布。
