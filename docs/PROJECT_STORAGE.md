# 系统资源与项目文件

系统资源仍由安装目录管理：`data/reference/` 保存 JCR、MeSH 和 Sci-Hub Bloom；运行时、本地模型与依赖留在安装目录。`data/research/` 仅保存共享服务配置和系统状态，`config/storage.json` 保存工作目录与项目文件夹映射。用户密钥不会复制到项目数据库。

设置 → 外观与存储：选择项目工作目录或输入绝对路径，点击“保存并迁移项目”。默认工作目录为安装目录下的 `workspace/`。迁移前要求没有正在执行的检索、聊天、下载；先复制并逐文件校验 SHA-256，成功后切换路径并删除旧位置的项目文件夹。目标目录同名项目不会被覆盖，失败保留原位置。暂停的下载任务在迁移后可以继续。

新建项目时分别填写显示名称（支持中文）和文件夹名。文件夹名为 1–64 个英文字母或数字，不允许空格、中文、下划线和连字符；排除 Windows 保留名，名称不区分大小写判重。旧项目自动保留兼容的目录名，例如 `gut`、`neuro`。

```text
工作目录/
  gut/
    project.json                  # 项目信息及编辑状态
    README.md                     # 目录说明
    pubmed/
      current.xml                 # 当前检索式合并、去重、筛选后的文献
      queries/                    # 各检索式的原始 XML 与执行历史
      snapshots/                  # 合并集合历史快照
      exports/                    # XML 导出
    pdf/<PMID>.pdf                # PDF 原文
    abstracts/<PMID>.md           # 下载失败时保存的 PubMed 摘要
    logs/<批次ID>/                # 下载报告、逐篇日志、批次快照
    markdown/                     # 清洗后的全文；raw/ 原稿与 assets/ 图片
    vectors/                      # 文本块、向量缓存、源文本快照与索引状态
    notes/notes.json              # 阅读笔记
    review/                       # 综述工作区、大纲、正文及生成来源
    packages/current-literature.zip
    metadata/
      research.sqlite3            # 此项目的检索、成员关系、助手对话
      downloads.sqlite3           # 此项目的任务、尝试历史与文件登记
      downloads/<PMID>.json       # 来源、版本、校验值
```

项目运行数据独立保存在各项目的 metadata 数据库；JCR、MeSH、模型配置等仍共享。文件登记使用项目相对路径，更换工作目录不破坏 PDF 和 XML 关联。

## 项目选择与删除

左上方下拉菜单统一提供项目切换、创建和“删除当前项目”；侧栏下方不再重复展示项目列表。侧栏在短窗口可滚动访问任务中心。

删除时需输入项目显示名称。确认后，完整项目文件夹移入当前工作目录 `.trash/<原文件夹名>-<唯一标识>/`，仍保留所有文件、占用磁盘空间；项目从列表移除，自动选择下一个项目，最后一个删除后显示创建入口。暂未提供界面恢复或清空备份功能；迁移工作目录不会移动旧 `.trash`。其他项目和全局模型设置保持不变。

删除沿用工作目录独占锁，检索、聊天和后台工作期间不执行；待启动的下载、转换、索引、综述和一键流程也须结束，暂停下载须先取消。目录移动后提交 `config/storage.json` 中的删除记录（包含备份路径），提交失败原位回滚；读取项目列表过滤删除记录，Rust/Python 路径解析与状态保存均拒绝复活已删除 ID。正常自动保存稍后压缩列表，删除记录提交后退出也不会丢失删除状态。

验证：`scripts/test-project-deletion.py` 使用临时目录和真实 Rust RPC 覆盖文件保留、其他项目、最后一个项目、旧请求拒绝、锁竞争、排队流程、路径校验和提交失败回滚；`scripts/test-project-deletion-ui.mjs` 使用独立 Vite 与真实 RPC 验证删除确认/取消、切换、刷新空白页、重新创建，以及 700/600/450 像素高窗口的任务入口。

## 文献库中的文件操作

- **打开项目文件夹**：直接打开 Finder / 资源管理器中的当前项目。
- **打包目前 PDF**：读取 `pubmed/current.xml` 中的 PMID，仅收录对应的现有 PDF 和摘要 MD；同时附当前 XML、清单和缺失 PMID。不会把历史检索中已排除的论文打入包。摘要文件可以独立打包。输出固定为 `packages/current-literature.zip`，校验新包成功后替换旧包，清理应用旧版生成的下载压缩包；失败保留原包。普通打包不会发起网络下载，也不会凭空生成摘要。
- **清空 PDF / 摘要（调试）**：确认后删除当前项目 `pdf/*.pdf`、`abstracts/*.md` 和 `packages/*.zip`，清除文件登记并记录清空事件。保留 XML、检索式、历史下载报告、笔记、综述及其他项目；不会在本次升级中自动执行。运行中或暂停的下载批次需要先完成或取消。

首次升级会迁移旧目录及全局数据库中的项目数据，在 `backups/storage-migration-v1/` 保留一次恢复备份。备份是升级前的历史副本，不参与当前项目的下载、清空或打包。移动工作目录时不要手动移动正在使用的数据库；请使用设置中的迁移操作。

## 当前集合与冗余文件

当前 XML 移出的 PDF 自动归档到 `pdf/redundant/`，对应摘要、全文 Markdown、图片、文本块与向量数据删除。重新纳入后只恢复 PDF，Markdown 与索引重新生成。全文原稿位于 `markdown/raw/`，清洗稿位于 `markdown/`。模型、运行环境仍属于 app 内系统资源。详见 [完整规则](MARKDOWN.md)。
