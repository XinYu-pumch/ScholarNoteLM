# 文献来源、检索工作台与检索助手

文献来源支持可执行的 PubMed 检索式与固定的 Zotero 导入快照。所有文献以 PubMed 主体记录的 PMID 去重，来源关系分别保留。

## 使用顺序

1. 设置模型与服务，用于检索助手；PubMed 检索本身不依赖 LLM。JCR 参考表在新安装中自动校验并启用内置默认，也可上传替换，MeSH 本地核验需要可用索引。
2. 在“文献来源”添加检索式，或将助手建议加入管理。新条目默认相关性、30 篇，不限日期/JCR。
3. 保存后明确执行；修改筛选只影响对应来源。执行成功更新该来源 XML，再合并当前集合。
4. 可在同一页导入自 Zotero、批量筛选、导出 XML；全部重新检索和归档视图在更多菜单。检索助手不提供 XML 导出。

GUI 不再提供 XML 上传入口；旧 XML 来源仍可查看、停用和归档，后端 `xml.import` 保留供兼容及隔离测试。上传接口要求 PubmedArticleSet、有效主体 PMID，支持 PubmedArticle 与 PubmedBookArticle，不从参考文献里取 DOI/PMID。

## PubMed 数量、筛选与停止条件

当前界面采用“前 N 条”探索检索：

1. 将原检索式组合为 `(检索式) AND hasabstract`。发表日期通过 `datetype=pdat` 在 PubMed 服务端限定；排序为相关性或发表日期。
2. ESearch 获取最多 **9,999 个候选 PMID**。该窗口适配 PubMed ESearch 的约 10,000 条可取回边界及当前响应行为，不表示整个 PubMed 只命中这么多。
3. EFetch 每批读取 **100 条 XML**，按候选顺序核对每个 PMID。强制保留有摘要的记录，再应用本地 JCR 筛选。
4. 合格数量达到目标就停止，否则继续下一批，直到候选耗尽。最后一批可能多出合格条目，来源只纳入目标数量；不同来源合并后再按 PMID 去重。

例如日期窗口很窄、Q1、目标 50 篇：先搜索这个日期范围内的候选，再逐批抓取和筛选；可能检查数百篇才得到 50 篇，也可能整个窗口不足 50。不会为凑数扩大日期、放宽分区或跳出候选窗口。

| 结果 | 界面提示 |
| --- | --- |
| 达到目标 | 来源显示“已完成” |
| 候选不足以达到目标 | 来源显示“已完成 · 数量不足” |
| 全部命中候选已经检查完 | 详情显示“候选已查尽，数量不足” |
| 候选窗口已用尽，但总命中更多 | 详情显示“已达候选获取上限” |

详情同时展示命中数、已抓取候选数、合格数和目标。没有专门的数量不足弹窗，批量完成通知只说明检索执行情况。符合条件的已有结果仍正常保存。

后端为历史数据保留完整收集模式：按发表日期递归分区并检查去重数量；单日仍超限或响应不完整时报错。当前 GUI 不提供新建全量检索入口，修改目标数量会改为探索模式；历史全量策略未改数量时可保留原模式。不能把后端兼容能力描述为常规界面选项。

NCBI 请求串行限速、至少间隔 360 ms、最多 3 次尝试；EFetch 每批 100 属于分页，不是合格文献总数上限。超时、重试和响应完整性检查保持原规则，缺失/重复/非法 PMID 不当作正常“数量不足”。

## 更新与来源合并

- 保存与执行分离，只有成功且修订号仍匹配才替换当前执行；失败保留旧结果，成功零命中则替换为空结果。
- 查询文字、日期、排序或模式改变需要重新搜索候选；条件相同可复用成功的候选快照，数量/JCR 变化按当前条件补抓或重筛。候选缓存不会自动拓宽范围，“全部重新检索”可主动重新获取。
- 待更新判定只比较生效条件：JCR 关闭时忽略分区；开启时按分区集合比较，顺序和重复项无影响；旧 `unknown` 字段不参与现行筛选。
- 同一 PMID 只要仍被一个启用来源纳入，就保留在合并集合。停用/归档只移除该来源贡献，不删除其他来源的文献。
- `pubmed/current.xml` 是检索数据库的派生文件，不通过手工删 XML 改变集合。集合变化后的 PDF/Markdown 备份与索引清理由 [生命周期规则](ARTIFACT_LIFECYCLE.md) 管理，历史 XML 与运行记录保留。

## JCR 参考数据

源码内置 `services/reference/jcr/default-2025.xlsx`，包含 22,249 条期刊类别记录（不等于独立期刊数）。新安装无已选参考表时自动校验、生成索引并启用；已有用户当前的参考表不被覆盖。“恢复默认分区表”优先使用内置文件，旧安装的 `data/reference/jcr/default-2025.xlsx` 仍作为缺少内置文件时的兼容回退。上传或恢复时若校验失败，保留当前已选参考表。

读取 `.xls` / `.xlsx` 第一个工作表，必需列为：

`Journal, ISSN, eISSN, Category, Total citation, JIF, Quartile, JIF rank`

要求有数据、Journal 非空、非空分区为 Q1–Q4（忽略大小写和首尾空白）。N/A 等缺失值作为警告，不冒充合法分区。文件校验失败不激活新版本；参考文件与标准化记录在系统 `data/reference/jcr/`，按 SHA-256 标识版本，不按项目复制。

ISSN/eISSN/ISSNLinking 优先匹配，期刊规范化名称作无歧义回退。同一期刊保留所有类别，任一类别命中所选分区即可纳入。**启用 JCR 后，无法匹配或无有效分区的文献排除**；没有“未知分区仍保留”的当前选项。更新参考文件后重筛相关来源。实际记录数量以所加载文件为准。

## 导入自 Zotero

- 只读 localhost API 的个人库。集合树可搜索、跨分支多选；父集合包含子集合，重叠范围按条目 key 去重。再次打开恢复上次选择与展开状态；改变选择须重新预览。
- 预览冻结标准条目快照，无有效 DOI 的条目跳过并记录。DOI 每 50 个一批，用带引号的 `"DOI"[aid]` OR 查询，随后 EFetch 并与文献自身 DOI 精确核对；无匹配、歧义和请求失败分开记录。
- 每次导入是独立来源快照，不生成可执行检索式，也没有更新/重新检索按钮。来源可改名、停用、归档；重复 PMID 合并但保留来源。
- Zotero 导入不继承日期、目标数量、JCR 或强制摘要筛选，也不参与统一筛选设置。
- 仅读取本次选中条目的附件，复用标题白名单、补充材料排除和优先级；**不限制 linkMode 或附件 HTTP URL**。可读本地 PDF 复制到项目，保留 Zotero 原文件，不覆盖现有项目 PDF。下载器末轮 Zotero 补充有另一套较严格规则，见 [PDF 下载](PDF_DOWNLOADS.md)。
- 启动即创建待处理来源行；提交成功更新同一行。提交前取消保留没有 XML 的来源及任务状态，提交后取消保留已经提交的元数据/PDF。离开页面不停止后台任务，来源页和任务中心可查看进度与报告。
- 快照、批次 XML、诊断和报告在 `metadata/zotero-imports/<任务ID>/`；自动化调用 `zotero.start --wait` 的 CLI 用法见 [开发说明](DEVELOPMENT.md#自动化启动-zotero-导入)。

## 检索助手与模型

不设单条输入字符上限，发送当前分支全部有效历史，不仅保留最近 12 条；不自动压缩或截断。一次流式请求返回策略说明和检索式，完成后本地 MeSH 核验；不自动查询 PubMed 命中数，用户点击“加入检索式”才建立草稿。

程序检查常见字段名称/别名、括号、引号，保留 PubMed QueryTranslation 和警告。语法或 MeSH 核验通过不意味着策略查全。

普通配置使用 OpenAI Chat Completions 兼容协议，温度为空不发送，不发 `max_tokens` / `max_completion_tokens`。Go 原生协议由独立供应商模块处理，不能把其专属请求头加到普通配置上。所有外网请求跟随当前系统 HTTP(S) 代理，无代理直连，本机接口绕过代理。

## 对话、分支与快捷键

- 左侧「我的对话」按项目隔离；＋ 新建独立对话，通过条目管理菜单重命名，点击列表切换。历史对话保持可读。
- 用户消息可「编辑重发」，助手消息可「复制」与「重新生成」。编辑重发/重新生成都会创建新分支，保留原对话及之后的消息；新分支携带分叉点之前的上下文。
- 每条消息提供「从这里开启新对话」，复制到该消息为止的上下文，随后可继续输入。分支用编号与来源名称区分。
- Enter 换行；macOS ⌘ + Enter、Windows Ctrl + Enter 发送；输入法组合输入期间不会触发发送。
- 输入框固定在聊天区底部，仅消息区滚动；用户向上阅读时不会强行滚回底部。消息样式遵循统一 Design System，适配浅深色主题。
- SSE 到达即显示正文和服务商实际返回的推理内容；兼容 reasoning_content、reasoning、可见 reasoning_details.text 与 content 中的 `<think>` 标记。不生成或虚构推理内容。推理在输出时展开，完成或停止后自动折叠，可手动展开查看。
- 测试连接收到正文或推理即成功；请求超时按等待响应/新数据计算，持续输出推理不会因总时长超过该值而失败。支持停止生成，已接收内容保存；截断、超时或服务错误保留部分回答与错误提示。
- 切离检索助手页面不会取消生成；不同对话可同时运行，“停止生成”仅作用于当前对话。刷新、重启后恢复已保存的消息，不等于自动恢复中断请求。
- 右键对话或点击条目的管理按钮，可重命名、复制、删除；“选择对话”支持全选和批量删除。
- 顶部“对话目录”按提问编号，支持搜索、跳转和回到最新；侧栏可收起，长标题不撑宽列表。

## MeSH 索引与自动更新

官方来源：

- https://www.nlm.nih.gov/databases/download/mesh.html
- https://nlmpubs.nlm.nih.gov/projects/mesh/MESH_FILES/xmlmesh/

使用官方压缩 XML 批量源，不逐词抓取全库；包含 Descriptor 主题词、Qualifier 限定词和可选 Supplemental Concept 补充概念。年份、条目数量以本机活动索引及设置状态为准，不假定已安装某一年的词库。

索引保存规范名称、唯一 ID、同义词、范围说明、分类树、允许的限定词及补充概念映射。SQLite FTS5 提供本地全文查词。词库年份与应用解析格式版本分开管理。

自动更新默认开启：应用运行期间每小时检查是否到期，7 天到期后访问官方目录，发现新生产年或文件 ETag / Last-Modified 变化时更新。失败至少间隔 6 小时重试。应用关闭时不安装系统常驻任务，下次启动补检查。设置中可手动检查、关闭自动更新、决定是否包含 SCR。

每次使用新的版本目录构建，验证下载长度、记录 SHA-256、解析结束、主词条数量和 SQLite 完整性，全部成功后才切换数据库内的活动指针。原索引持续可读，失败或应用退出不破坏旧版本。同版本字节已核对的官方源可以复用。

## 数据位置

所有路径相对 ScholarNoteLM 根目录：

| 内容 | 位置 |
|---|---|
| 模型服务配置等全局设置 | `data/research/research.sqlite3` |
| 本项目检索式、执行记录、来源关联、集合版本、助手对话 | `<工作目录>/<项目>/metadata/research.sqlite3` |
| JCR 文件与内容版本 | `data/reference/jcr/` |
| MeSH 原始压缩文件、清单与 SQLite FTS5 索引 | `data/reference/mesh/<版本>/` |
| 每次检索的原始响应与合并原文 | `<工作目录>/<项目>/pubmed/queries/` |
| 不可变集合快照及清单 | `<工作目录>/<项目>/pubmed/snapshots/` |
| 当前集合 XML（可重建输出） | `<工作目录>/<项目>/pubmed/current.xml` |
| 导出的 XML | `<工作目录>/<项目>/pubmed/exports/` |
| 项目列表、当前项目、主题等界面状态 | `data/prototype/state.json`（全局状态，项目细节存于各自 project.json） |

模型密钥保存在研究数据库中；常规设置响应只返回“是否已保存”，不返回密钥。macOS/Linux 下研究目录权限为当前用户独占。数据库未做应用层加密，请将含凭据的数据库视作个人配置，勿分享。项目 `.gitignore` 已排除 `data/`、`config/` 和 `workspace/`。没有读取或复制 BADR 的模型凭据。

## 开发与测试

Rust 研究引擎同时服务 Tauri IPC 与 Vite 的 CLI 桥接；浏览器桥限制同源 JSON 请求。测试入口与隔离要求见 [开发说明](DEVELOPMENT.md#测试入口与隔离)。`test-pubmed-live.py` 会访问真实 NCBI；UI 脚本须先读并连接隔离服务，不能统一假定它们不会触碰真实数据。

## XML 快照存储

新查询、导入和合并集合将原始 XML 按字节哈希无损压缩到项目内 `pubmed/objects/<hash>.xml.gz`，清单的 `xmlPath` 指向共享对象。来源、筛选及执行历史各自保留；相同内容复用，不同内容独立压缩。合并快照的存储路径不参与原有集合签名。当前 `pubmed/current.xml` 和显式 XML 导出仍是普通 XML；历史明文快照兼容读取，压缩内容读取时校验哈希。


### 双语行为

检索助手每个对话保存回答语言，新对话采用设置默认值。中英文提示词均保持 PubMed 语法及英文医学检索词；语言只改变讨论与说明。后续提问采用当前对话语言，重新生成沿用原消息语言，分支继承分支点。界面切换不改写历史。

## 可选模型供应商

“模型与服务”中的 `opencode_go` 是默认折叠的独立分组，只保存一份同名配置，无需新建多个配置；展开后填写密钥、获取模型列表、选择模型并保存。各模型行独立选择思考强度，档位由模块按模型登记，初始为“服务端默认”；未登记档位的模型保持默认。地址由模块管理，用户无需分别填写模型端点。模型仍可在检索助手、综述大纲/正文、文献问答和阅读聊天中选择。既有普通配置不会按名称自动转换，也不自动更换全局默认。

Go 特殊头与原生协议转换集中在独立模块，普通 OpenAI 兼容请求继续使用原逻辑。停用模块后保留旧配置供删除，调用时明确提示不可用。维护与删除方法见 [可选 LLM 供应商](../services/llm_providers/README.md)。
