# PDF 下载状态与派生材料的依赖

2026-09-29。

## 本次实现

文献库 PDF 面板增加“当前下载状态最新”，同时显示未获取全文和摘要替代数量。

- 当前每篇文献已有有效 PDF，或者在完成的批次中实际走过下载流程，即视为下载处理已覆盖。
- 没有摘要的失败/延期条目也可属于已处理；不会因此伪造全文或摘要可用状态。
- 最新状态下仍有缺失 PDF 时，主按钮为“重试未获取项”；全部已有 PDF 则禁用下载。
- 有未处理文献时，主按钮仅提交 pendingPmids，避免重复处理已经完成尝试的缺失文献。
- 新增文献、已有成功 PDF 被删除或损坏、补充/改变 DOI 或 PMCID、清空 PDF、启用新下载来源使相应缺失文献待处理。
- 单纯修改并发或超时不自动让完成记录过期；仍允许主动重试。
- 暂停/取消批次不替新文献完成处理，也不抹掉此前完整批次的处理结果。
- 下载配置保存后刷新 PDF 状态读取。

实现位置：artifact_state.download_status -> markdown.status.downloadStatus -> LiteratureWorkflow。
没有修改下载引擎的来源顺序，也没有删除历史记录。

## 与问答、综述的关系（核对与建议，非本次新增功能）

面板的“最新”是汇总显示，不应作为派生内容有效性的唯一依据。

- PDF 内容变更应使依赖它的 Markdown/索引待更新。
- Markdown 内容变更应使对应检索材料版本变化，新的生成使用当前材料。
- Embedding 配置或索引变更影响后续检索；不直接证明历史回答或正文错误。
- 综述大纲使用主题、要求与摘要合集，不直接依赖 Embedding。
- 现有问答保存 sourceSignature、embeddingFingerprint 等，生成中检查变化，恢复检查点时也进行匹配。
- 现有综述正文依赖 source_signature、检索/模型签名和提示词包；不匹配时已有正文显示待更新。当前签名包含项目整体材料及索引代际，是较保守的判断。
- 原有回答、正文及证据快照应保留；统一的历史回答“材料已更新”提示、精确到引用文献的影响范围属于后续独立界面/依赖改进，本次没有自动改写任何内容。
