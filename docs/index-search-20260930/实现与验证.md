# 索引进度与合格检索结果更新

完成日期：2026-09-30。

## 索引与进度

- 自动模式按文献追踪缺少的向量。一篇文献的向量齐全后，即交给本地写入线程；其余文献继续请求 Embedding。写入队列有上限，避免内存无限增长。
- 初始扫描只做一次完整核对，写入前按篇核验版本、实际输入、元数据和纳入状态，减少逐篇重复扫描整库。
- 文献库与任务中心直接显示两个进度：向量准备的唯一文本块数、已完成写入或复用的文献数。固定并发和自动模式都使用独立的轻量进度接口；运行中约每秒读取一次，不等待材料状态扫描。
- 正常并发更新期间的 UI 快照标记为刷新中，不再把持续写入当成红色错误。此快照不用于证据有效性判断；问答、综述及索引发布的有效性核验保留。
- 动态调度仍使用当前已验证 tokenizer 的实际 token 数及余量；无法验证匹配时回退到每块 8192 token 的保守预算。网络恢复、RPM/TPM 限速逻辑保留。
- 生成向量需要远程 Embedding；缓存命中、向量写入和索引有效性核验在本地完成。这里完成的是流程优化，未用真实服务重新生成全项目向量，因此没有宣称具体提速倍数。

## 检索规则

- 检索时追加 `hasabstract`，再解析 XML 核查真实摘要；空的结构化摘要标签不视为摘要。有 PDF 也不能替代此项入选条件。
- 数量表示每条检索式筛选后的目标篇数。按 PubMed 返回顺序分批获取 XML，经摘要、日期和 JCR 条件筛选后继续补足。
- 开启 JCR 筛选时，无匹配分区的文章不计入目标数。各检索式独立满足目标，合并集合按 PMID 去重，不强求各检索式之间互不重复。
- **更新待处理检索（N）**：处理未生成 XML、检索条件或筛选规则有变化的条目；条件允许时复用已保存候选 XML 和候选 PMID 列表。
- **全部重新检索**：对当前启用的检索式重新获取 PubMed 结果。成功后发布该条的新结果；失败或中止保留该条旧结果。
- **中止检索**：中止当前请求和后续队列。
- 已查尽但数量不足的条目标记“数量不足”，不会一直被当成待处理。限量检索最多检查前 10,000 个候选，达到该上限会明确提示，不冒充全部查尽。
- 旧运行记录及原始 XML 保留；无摘要文献的现有 Markdown、资源和编辑历史归档，PDF 沿用冗余文件归档机制。
