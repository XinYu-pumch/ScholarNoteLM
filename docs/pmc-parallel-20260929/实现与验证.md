# PMC 双路下载实现与验证

第二步仅对已有有效 PMCID 的文献，让 PMC S3 与 Europe PMC getPdf 同时工作；其余文献直接进入后续来源，不再按 PMID 补查。S3 正序默认 5 路，getPdf 倒序默认 4 路；按 PMCID 数字排序，共享领取/成功状态，不重复下载同篇。失败可直接由另一来源接手，两路失败后才进入原有后续来源。

- getPdf 直接请求 `https://europepmc.org/api/getPdf?pmcid=PMC编号`，不使用 FTP、ZIP 或旧深度补救适配器。
- 流式临时文件、PDF 签名/结构/大小校验、SHA-256、原子发布、失败和取消清理均已接入。
- 默认 15 秒连接上限、60 秒单次总时限、最多 3 次请求；429 共享冷却，暂停后继续保留 Retry-After 与请求次数。403/404 不盲目重试。
- 设置页新增 getPdf 参数，旧配置自动获得默认值；后续 Sci-Hub、Unpaywall、增强补救、Zotero 顺序不变。
- 报告区分来源，并提供 `pmcParallelWallSeconds`；来源耗时相互重叠，不相加当作批次耗时。

## 验证

- 13 项专项测试通过：正反数字排序、5+4 并发上限、互补无需整轮等待、同篇独占、两路失败后进入后续步骤、继续时不重放已完成来源、仅有效 PMCID 入队、无 PMCID 时两来源零请求、双路取消与继续、已有 PDF 复用、开关、错误状态/伪 PDF 拒绝、有限重试/限流/超时清理。
- 下载、下载流水线、Sci-Hub 重试、历史来源缓存、缺失 PDF 报告、Zotero 和页面状态缓存相关回归通过。原先断言严格串行来源列表的测试已更新为并行阶段；Zotero 仍位于末尾。
- TypeScript 与 Vite 生产构建通过；保留原有大于 500 kB 的 bundle 提示。
- 设置页验证默认值、保存和 1440 / 1000 / 800 像素布局，无页面错误；截图同目录保存。
- 两篇真实文献在隔离目录中验证：PMID 32944205 / PMC7477725 经 S3 下载 138654 字节；PMID 34553703 / PMC8478391 经 getPdf 下载 215625 字节。均通过应用原有 PDF 结构校验及落盘。
- 此次真实测试使用每来源 1 路以覆盖两路同时工作；双路阶段 6.645 秒，总批次 6.701 秒。默认 5+4 并发由离线专项测试验证。本次小样本不是全量速度或成功率基准。

本轮更新源码和前端构建，未重新制作旧 macOS 安装包。开发版下一次新启动的下载 worker 会加载新逻辑；正在运行的 worker 不热替换。PrimaryMN 的 PDF、配置和下载数据库未被测试修改。
