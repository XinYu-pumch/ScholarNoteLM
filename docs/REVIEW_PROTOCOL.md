# 综述共享材料与正文协议

当前材料/输出协议为 `review-unit-object-refs-v3`；材料读取还支持 `review-unit-resource-blocks-v2`，不接受 v1 材料包或旧 TXT 作为正式输入。旧版已生成正文继续可读、可导出，不自动改写。工作区操作、冻结材料和续写规则见 [综述工作区](REVIEW_OUTLINES.md)。

每个终末标题独立 query、独立召回 topK，同级终末标题按写作单元联合撰写。单元内按稳定 chunk ID / 资源 ID 去重；不按 PMID 合并不同原文，不做语义摘要或模糊去重，不跨单元混用证据。全部原文保留，不设置应用侧字符预算。

## 文件与模型请求

```text
review_parts/
  prompt_section_1.json       # 正式输入，包含单元、子标题、共享池和输出契约
  prompt_section_1.txt        # 程序生成的阅读预览，编辑它不改变实际请求
  resources/<sha256>.md       # 原文表格或图片原文标记
  resources/<sha256>.html     # 原文 HTML 表格
  resources/<sha256>.png      # 图片快照，也可为 jpeg/gif/webp
  section_1.json              # 已校验的联合写作结果
```

材料包顶层字段固定为 `schemaVersion`、`unit`、`task`、`retrieval`、`evidencePool`、`resources`、`outputContract`。

| 字段 | 内容 |
|---|---|
| unit | 写作单元、需返回的节点、父级与同级大纲背景；节点区分终末正文和导语 |
| task | 主题、语言、已有额外写作要求 |
| retrieval | 每个子标题的 query、召回证据 ID、原排名与已有评分 |
| evidencePool | 单元内按稳定 chunk ID 去重的原文，局部编号 E1、E2…；保存 PMID、来源类型、文档版本、位置、resourceIds、retrievedFor |
| resources | 单元内按稳定资源 ID 去重，局部编号 R1、R2…；保留内容文件及指纹、双向关联、资源前/后原文及其位置 |
| outputContract | 必须返回的 unit_id、完整节点编号和标题，以及正文 blocks 的结构约束 |

引用来源与使用权限分开：`retrievedFor` 表示哪些子标题找到了这个文本块；同单元内所有终末子标题都可以使用池内相关证据，包括兄弟标题召回的材料。导语仍不引用。

发送前，程序核对正式 JSON 的哈希、字段和引用关系、外置文件的路径和 SHA-256；读取并补入完整表格，给当前明确勾选支持图片输入的模型补入实际图片。文件路径不要求模型自行读取。未提供图片时明确标注模型只能使用文字。表格内换行、引号、Markdown 标记等作为 JSON 字符串数据，不用于划分小节边界。

同一个资源在一次请求中只有一份；源 MD 已经拆成多个对象的表格仍分别保留，不猜测拼接。图片与表格继续由原文位置关联，不识别图表名称。所有原始内容保持，不使用 LLM 预处理。

## 三种关系分开表示

1. `[E1]`、`[R1]` 是来源引用，展示为 PMID，不触发完整图表插入。
2. `resource` 块表示模型明确选择完整展示一个原文资源；`table` 块表示模型新整理的综述表。
3. `{{ref:R1}}`、`{{ref:T1}}` 指向本写作单元已插入的正文图表，由程序生成编号和链接，不增加插入动作。

图表只是材料时不自动出现于正文。模型仍须判断完整展示是否必要；新表可选择部分数据、重排、合并多个来源，或合并多个完整表。单位、人群、时间与必要注释仍须保留。程序不判断这些内容是否科学正确。

## 输出示例

```json
{
  "unit_id": "1",
  "sections": [{
    "node_id": "1.1",
    "title": "标题",
    "blocks": [
      {"type": "markdown", "text": "相关结果见 {{ref:T1}} [E1] [E2]。机制见 {{ref:R2}} [R2]。"},
      {
        "type": "table",
        "table_id": "T1",
        "title": "不同人群的研究结果",
        "columns": ["人群", "结果", "来源"],
        "rows": [["人群 A", "42", "[E1]"], ["人群 B", "7", "[E2]"]],
        "notes": "人群与观察时间不同，不直接比较 [E1] [E2]。"
      },
      {"type": "resource", "resource_id": "R2"}
    ]
  }]
}
```

- 新表的 `table_id` 是单元内唯一 T ID，不是最终表号。不同单元均使用 T1 不会混淆。
- `title` 不带编号，列名及单元格为字符串；每行列数一致，至少包含一个合法 E/R 引用。`notes` 为字符串，可为空。
- Markdown 块中不再夹带表格；生成表使用列和行数组，避免竖线、换行让表格错列。单元格支持行内 Markdown，HTML、嵌套表格等会被拒绝。
- 正文不手写“图1”“表R5”“Figure 2”等编号；使用交叉引用标记。禁止伪造内部锚点和图片路径。
- 交叉引用允许先引用后展示，也允许指向同一联合写作单元内其他子标题的图表；不允许引用只在材料池中、未插入本单元正文的图表。仅需引用材料时使用 `[R1]`。
- 父标题导语仍不带文献引用、原文资源或生成表格。

校验完全由程序执行：节点与标题匹配、合法证据 ID、资源版本绑定、图像输入资格、T ID 唯一、目标存在、行列齐全、逐行引用、禁止手写编号。既有的格式失败联合修复流程保留，没有新增独立语义审核模型调用。校验通过不代表数值或推论正确。

## 全篇编号与跳转

装配按完整大纲顺序预先分配编号，与异步生成完成顺序无关：

- 图片使用一个图号序列；原表与生成表共用一个表号序列。
- 同一稳定原文资源复用同一编号，每次展示使用独立锚点，避免 HTML 中重复 ID。
- 同一资源多处展示时，优先跳转到当前节点中的展示；否则指向同单元中的首次展示。
- 新表身份由所属节点与局部 T ID 共同确定，不同单元不互相覆盖。
- 原图内部印刷的原论文图号仍是图片的一部分，程序不会修改图片。综述正文引用以装配标签为准。

app、HTML、Markdown、Word 使用同一编号和对象对应关系。app 小节预览引用到同级其他小节时会打开全文预览并定位目标。HTML 使用离线锚点；Markdown 导出锚点与相对资源路径；Word 导出内部书签与链接。Markdown 阅读器需支持 HTML 锚点才可点击跳转，但编号仍完整可见。

完整原图的关联文字仍按原文位置提供，明确标注“不保证为完整图注”，不自动猜测相邻段落就是图注，也不自动拼接不同原图。来源转换中的缺字、错列与语义层级丢失不会因统一编号而修复。

## 引用与存储

- `sourceBlocks` 保存原始块结构，包含生成表每个单元格内的原始 E/R 引用。
- `sourceMarkdown` 保存兼容文本表示，包含未装配的交叉引用标记；最终编号只在展示/导出时确定。
- `citationRefs` 保留全部不同证据 ID、文本块/资源 ID、PMID。生成表中的引用也全部提取。
- `blocks` 保存已绑定资源、已转换 PMID 的正文和结构表；`displayBlocks` 是带编号、锚点及安全 HTML 的派生显示数据。
- 仅同一处连续引用中的 PMID 去重，不跨句子、行或表格单元格去重。
- 图像必须确实随本次请求发送，才允许插入；这不能证明模型已经正确理解图像。

## 旧综述

旧正文及证据不会自动改写。v1/v2 正文中的自由文本图号没有可靠对象身份，程序不会猜测其对应关系。检测到这类编号或旧 Markdown 表格时，预览/新导出提示该单元尚未使用统一编号。

要采用新协议，重新准备提示词并生成相应写作单元；无需重新下载 PDF、清洗或向量化。现有静态 HTML 不会自动改变。旧资源块仍可装配，旧正文仍可阅读和导出，但仅重新导出无法可靠修正原先自由文字中的图号。

## 发布校验与修复

返回必须符合本单元的 `unit_id`、完整 `sections`、节点编号与标题。证据 ID 经范围校验后确定性转换为 PMID；正文按大纲顺序装配，不按模型返回或并发完成顺序排序。

结构或引用失败时，最多使用同一共享材料池及相关图片联合修复一次，仍失败则不发布。原始响应、实际请求和修复请求保存于任务日志；网络故障不因格式修复机制而无限重试。发送和发布前再次校验正式 JSON 与外置资源；编辑 TXT 预览不影响实际输入。

引用与资源校验确认归属和可追溯性，不保证论断被原文支持，也不保证不同小节没有矛盾或重复。HTML 的自包含证据池和稿件共享图片存储见 [文件与导出](REVIEW_OUTLINES.md#文件与导出)。

## 验证

`test_review_objects.py` 验证前向/跨节点交叉引用、局部 ID 隔离、共享表号序列、来源保留、悬空目标与非法表格、旧版兼容，以及 HTML/MD/Word 中真实唯一的锚点/书签。

`test-review-shared-pool-ui.mjs` 验证实际组件的小节/全文跳转、结构表格和离线 HTML 图表跳转。`test-review-writing-integration.py` 通过真实桌面 RPC 与 worker、隔离的本地模型响应验证结构表保存与三种导出，不请求外部 LLM。
