# 页面加载与后台刷新优化方案

日期：2026-09-29。状态：代码检查与接口测量完成，尚未实施性能改动。

## 范围与目标

覆盖项目概览、文献库、检索工作台及检索助手、综述大纲、综述撰写、文献问答、阅读与笔记、任务中心和设置。保持检索、生成、引用、材料有效性判定及自动任务衔接的既有语义。

目标体验：首次进入分区加载，已读内容再次访问时立即恢复；状态变化后台同步；只让确实依赖尚未就绪数据的操作等待。缓存不改变磁盘文件和业务数据库的权威地位。

## 已确认的问题

### 全局

- `App.tsx` 页面按项目和页面 key 重建，局部读取结果、筛选状态及滚动位置不会自然保留。
- `context.tsx` 的文献同步依赖 page，任意页面切换触发 workspace；检索工作台自身又读取一次。结果未变时仍生成新的顶层 state 对象，触发持久化路径。
- workspace 并非纯读取：重算合并文献/JCR、写 current.xml、调用文件协调。界面导航触发了维护工作。
- App 外层每 2 秒调用 download.list；文献库、检索工作台、任务中心、阅读页面各自再创建一个相同轮询。每个 hook 的 pending 标识不能跨组件去重。
- download.list 返回历史批次全部条目和全部附件，还执行文件协调、恢复任务、启动排队任务及转换后续衔接；不可直接删除轮询而忽略这些职责。
- 通用 research-changed/downloads-changed 事件刷新范围过宽；模型下拉框各自读取模型池。
- Python RPC 每次启动独立进程，因此进程内解析缓存不能跨请求复用。应先减少重算和请求数，再判断是否需要常驻服务。

### 页面

- 文献库：下载、转换、索引、流程状态分别每 2 / 2.5 / 4 / 1.5 秒刷新，空闲时也运行。vector.status 重复检查全文与文本块。
- 项目概览：每 5 秒调用 library.overview；为几个数字调用完整 Markdown 状态检查和全文索引有效性检查。
- 综述撰写：可见但空闲时每 2.5 秒完整 status，运行时每 1.2 秒；status 扫描全项目来源签名和各写作单元。隐藏的撰写组件初次挂载仍会读取状态及选中章节；首次直接可见时初始化与可见性 effect 可重复请求。
- 综述大纲：list 后串行 get；隐藏撰写页额外工作。大纲本身已有仅运行时轮询，不必归类为持续空闲重算。
- 文献问答：inventory 阻塞历史对话读取；每 5 秒重复读取完整当前对话，即使没有正在生成的回答。inventory 重复解析全文、过滤文本块并读取向量内容。
- 检索助手：自身接口很快，但首次挂载的两个 effect 均调用 chat.list；工作台请求及全局刷新占更大比重。
- 阅读与笔记：已有项目内存数据可直接展示，主要额外开销来自重复获取全项目下载记录。
- 设置：本地配置读取很快，优先级较低；MeSH 轮询不区分当前设置分类和任务活动状态。

## 第一阶段：统一前端读取与页面恢复

1. 建立应用级只读查询缓存，以资源种类、项目 ID、工作区/会话 ID、模型配置或资源版本为键。相同进行中请求合并，同一数据供多个组件订阅。
2. 按资源设置容量上限和淘汰规则；轻量列表与大体积正文分开缓存。不把明文密钥放进通用缓存或 localStorage。
3. 将读取状态分为首次加载、后台刷新、操作提交，背景刷新保留已显示数据；失败时保留上次成功内容并明确状态，而不是清空页面或把旧数据标为最新。
4. 移除“导航就同步全部文献”的依赖，改为项目初始读取、相关变更和必要恢复时核对。数据未变时保留 state 引用，避免无意义自动保存。
5. 恢复各项目的选中对话、综述工作区、页签、筛选及滚动位置。输入草稿与服务器快照分离，后台刷新不得覆盖编辑；原有保存/取消/离开确认行为保留。
6. 问答历史、模型选择、文献状态各自加载；首屏不等待不相关的慢请求。未完成验证的发送/生成操作保留必要约束。
7. 隐藏的综述撰写页按需加载正文和详细状态；大纲只读取用于任务互斥的轻量活动状态。已有任务继续由共享任务管理追踪。

## 第二阶段：拆分后台状态与材料检查

1. 明确区分轻量任务状态、文献状态摘要、全文材料校验及维护操作；先建立可靠任务管理，再替换现有轮询。
2. 将下载恢复、排队启动、下载后转换、转换后索引等现有副作用迁入统一协调入口。保持幂等、互斥、崩溃恢复及取消语义，页面关闭不影响已启动任务。
3. 建立项目派生状态记录，供概览、文献库、问答及综述共享；不同页面保留各自统计口径，例如“全部块”和“可问答召回块”不可混淆。
4. 缓存单文献内容版本、图表资源指纹、文本块有效性和按 Embedding 配置计算的可检索计数。更新受影响的文献，不在状态请求中读取向量 BLOB 或重复解析完整 Markdown。
5. 问答 inventory 改成目录和有效计数查询；综述 writing.status 从当前材料版本与单元状态摘要判断待更新状态，避免每次全量计算来源签名。
6. 概览复用项目摘要；文献库读取列表和状态摘要；阅读页只获取当前文献附件状态；任务中心按需加载历史批次条目。
7. workspace 将读取与合并结果发布分开；检索式、纳入范围、JCR 等实际变化才重算并发布。恢复路径保留投影修复能力。

## 第三阶段：任务更新与大内容

- 按项目共享一次任务订阅。活动任务保持及时更新；空闲时使用轻量版本检查，窗口重新激活后核对，避免固定频率全量刷新。
- 现有流式通道继续负责实时回答；重连时补齐缺失版本，完成/失败/取消均强制核对最终快照。若保留轮询，使用单次在途请求及退避，避免旧响应覆盖新响应。
- 对话列表、正文、过程事件、证据详情分开读取；长历史分批加载。引用跳转需能自动补载目标记录，导出继续包含完整内容。
- 综述先显示目录和选中章节，整篇预览在打开时加载；按内容版本缓存 Markdown 渲染，未变化章节不重解析。
- 设置共享已保存配置；编辑草稿独立。MeSH 仅在必要时更新状态，不重复请求服务商模型列表。
- 完成这些优化并复测后，再评估常驻 Python 服务；暂不为减少小量进程启动开销引入新的长期进程生命周期。

## 缓存失效与正确性

| 变化 | 需要失效或更新 |
| --- | --- |
| 检索结果、纳入范围、JCR 条件 | 合并文献、列表、来源版本、相关统计及问答范围 |
| PDF / Markdown / 图表文件新增、替换、删除 | 对应文献指纹、可用材料、索引有效性、综述材料状态 |
| 建立、清空、重建索引 | 索引计数、问答范围、综述材料版本 |
| Embedding 配置变化 | 该配置下的检索有效性与计数 |
| LLM 默认模型/模型池变化 | 模型选择与依赖该模型的状态；不重建文献索引 |
| 对话或章节完成/修改/删除 | 对应记录与列表摘要，删除时清除缓存 |
| 项目切换/删除/存储位置变更 | 按项目隔离；旧在途请求失效；删除清理缓存 |

外部修改文件必须被发现：文件变更通知、窗口恢复时检查和低频轻量核对作为发现机制；实际开始问答、生成、索引前仍验证依赖。缓存记录应包含版本，无法确定最新时标为待核对。文件变化与发布过程中使用现有锁和原子发布机制，避免半成品状态。

## 实施顺序与验收

顺序：共享请求/下载订阅及导航同步 → 问答分区加载和页面恢复 → 项目材料摘要（文献库、概览、问答、综述共用）→ 综述状态与内容拆分 → 长记录加载及设置收尾。

先记录改造前后的完整页面时间，再设定正式性能门槛。当前建议目标（不是已测结果）：

- 同项目重复进入，已有主要内容在 100～200 ms 内恢复；后台检查不造成整体闪空。
- 冷进入历史对话/目录的可见时间目标 500 ms 内；材料检查独立显示进度。
- 空闲、数据未变时，连续 60 秒无全文解析、无向量 BLOB 扫描、无完整历史记录重复传输。
- 每份共享数据最多一个在途请求，活动任务更新无遗漏，常规状态变化目标 1～2 秒内呈现。
- 测试首次进入、反复切页、项目切换、重启、长对话、长大纲、任务进行中、外部文件变化、模型切换、删除数据、后台异常及编辑冲突。
- 校验优化前后文献集合、统计口径、有效/过期判定、引用定位、导出内容一致；验证下载→转换→索引自动衔接及崩溃恢复不依赖停留在某页面。

实现时补充有针对性的版本失效、请求竞争、任务恢复及结果一致性测试；使用真实桌面页面完成视觉与交互复核，报告冷进入和重复访问分别的耗时分布、请求次数与返回体大小。
