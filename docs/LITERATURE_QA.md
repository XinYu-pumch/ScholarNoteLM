# 文献问答（当前开发版）

文献问答不设问题字符上限，不截断当前轮累计材料与有效对话历史。历史整个材料池不会自动重发，按需读取其实际引用。输入超出模型服务限制时照常呈现错误。

主题问答采用“小综述”流程，与综述撰写共用正文召回、关联图表和引用渲染。上下文协议与人工评估方法统一记录于本文。

## 使用流程

1. 在文献库完成文献准备和索引，在设置中保存并验证 Embedding 配置。
2. 选择项目文献范围和回答模型。需要实际图像输入时，在设置 → 模型与服务 → 可用模型的对应行勾选“支持图片”并保存。
3. 发送问题。首次规划同时结合正式对话历史判断意图：闲聊或澄清直接回复；纯改写保留历史回答与引用绑定；依据追问优先读取历史实际引用；新的研究问题生成具体 query。
4. 需要检索时，每个 query 在所选文献的有效正文向量中按相似度召回 topK。按稳定 ID 合并命中块，并补入位置关联的完整表格、图片和附近文字。标题与章节路径只保留为来源信息，不拼入向量输入。
5. 规划模型根据累计材料判断覆盖是否足够。达到最少检索轮数且材料足够时写回答；不足且未达上限时补查询；达到上限时基于已有材料写回答，并说明材料局限。

默认每个 query 8 块、每轮最多 3 个 query、最少 1 轮、最多 3 轮；按用户设置生效。纯改写、闲聊、只读取历史依据不被强制凑检索轮数。普通 OpenAI 兼容请求不发送输出 token 上限；Go 原生 Messages 的必填参数例外见 [供应商说明](../services/llm_providers/README.md)。

自动挑选整篇全文并补入主题问答材料池的功能、提示和开关已删除。历史证据按需取回仍保留。GUI 新提问固定为主题问答，不提供项目概览或旧版单篇精读入口；旧概览后端及历史读取仍保留。

## 清洗、检索与来源

- PDF 使用 Marker 转换，并固定仅清洗参考文献。短正文、图注、表格保留。
- 召回排除少于 100 字符的 heading，保留长 heading；不使用 BM25、MedCPT 或本地重排模型。
- 图表作为材料不等于必须插入正文。模型判断展示必要性；生成表可摘取或合并材料，原图原表使用资源块。
- 未实际发送图片时，不允许把文字中的图号当作已经看图。勾选视觉能力只是配置，不能证明模型理解正确。
- 引用内部保留证据 ID；同一处连续引用按 PMID 去重，不删除不同句子各自的引用。图表编号、正文交叉引用与导出使用统一渲染逻辑。
- 主题问答执行程序结构与引用范围检查，不追加 LLM 事实后验证。结构通过不表示人数、物种或实验条件已被正确理解。

## 上下文、重试和对话管理

用户问题、追问和成功的正式回答组成对话历史。历史整个材料池不自动重发；`read_previous_evidence` 按需读取实际引用的原文和图表，并重新绑定本轮编号。纯改写不会为填补内容新增事实。

失败回答的“重新生成”或“继续未完成步骤”在原消息位置显示新尝试，日志仍按运行保存。可继续的检查点必须与当前输入和来源匹配；不匹配时需要重新生成。模型身份按实际端点、模型、温度、供应商参数和当前模型的图片能力比较；更换密钥、调整超时、复制相同配置、切换其他模型的图片开关不使新任务检查点失效。恢复时并发数和未开启 RCS 时的候选数可变，检索参数、实际模型、材料和问题仍须匹配。旧检查点通过原哈希精确验证后保留别名，继续复用已完成调用和证据卡；若旧密钥或历史模型列表已丢失、无法验证原哈希，则保守拒绝续跑，已有回答保留。Embedding 的密钥仍需通过连接验证。

左右切换对话或离开页面不隐式取消任务，不同对话可以同时生成。停止只作用于目标对话。对话列表支持右键重命名、复制、删除，以及选择/全选批量删除。顶部“对话目录”可按提问编号和文字搜索定位，也可回到最新。

## 设置

- 模型与服务：模型启用、默认模型、支持图片、连接/图片测试集中在模型行。
- Embedding 模型：启用已验证配置；高级参数中的 RPM/TPM 同时用于文献和 query 向量请求。“召回与重排”设置已删除。
- 文献问答：配置检索轮次、topK、每轮 query 数及规划/回答模型。旧概览相关后端设置保留，不代表 GUI 可新建概览任务。
- 模型请求默认跟随当前系统 HTTP(S) 代理；没有代理时直连，本机模型保持直连。系统代理开关或地址变化后，新请求和连接重试读取最新设置，不需要重启应用；已建立的流式连接不强行迁移。检索助手、阅读对话、综述和连接测试使用相同策略。

## 日志与验证

`<项目>/qa/threads/` 保存对话；`<项目>/qa/runs/<runId>/` 保存输入、进度、模型请求与响应、证据快照、`history-evidence.json` 和 `answer-bundle.json` 等产物。日志不包含 API 密钥。导出位于项目 `qa/exports/`。

可复现检查使用隔离项目和本地模型模拟服务：

```sh
runtimes/downloader/bin/python -m unittest discover -s services/downloader/tests -p 'test_qa*.py'
runtimes/downloader/bin/python scripts/test-qa-mini-review-integration.py
runtimes/node/bin/node scripts/test-qa-mini-review-ui.mjs
runtimes/node/bin/node scripts/test-conversation-ui.mjs
```

程序回归不代替学术质量评估。运行 UI 脚本前先检查脚本，并确认所连接的开发服务使用隔离根目录。人工评估示例见本文末尾。

## 请求日志存储

新任务的冻结输入 `input.json.gz`、请求 `*.prompt.json.gz`、返回 `*.response.txt.gz` 使用无损 gzip，问答推理日志同样压缩。直接在生成时生效，不需要维护脚本；重试、读取与历史稿件上下文兼容旧明文记录。任务状态、检查点、正文和模型协议不变，正在追加的 worker 日志保持普通文本。


### 双语行为

每个对话独立保存回答语言。规划、证据评估、直接回复、综合撰写和格式修复使用对应语言提示词，原文及协议字段保持不变。新轮次冻结语言；重新生成、检查点续跑及分支沿用原轮次语言。切换界面语言不改变对话设置。

## 上下文协议与并行运行

### 历史与材料的边界

- 按当前对话的可见消息顺序传入全部用户问题和成功的正式回答，不再只保留最近六轮。失败草稿、推理、错误日志和已被替换的尝试不作为回答历史。
- 每轮历史带 runId、正式回答的引用索引和图表目录。它帮助理解指代，不构成当前科学证据。
- 历次材料池保留在各自运行目录，默认不重新发送。新一轮的材料池由按需取回的历史证据与新召回材料构成。
- 新检索仍只召回符合规则的正文块，附带位置关联的完整图表与附近文字。短 heading 排除、长 heading 保留；自动补入整篇全文的代码和设置已删除。

### 历史证据工具

规划或材料判断可返回 `historyRequests`，每项使用 `read_previous_evidence`，提供当前上下文内的成功 runId。可指定 referenceIds（E/R）或 blockIds（生成表 T、资源 R）；省略选择条件只读取该回答实际引用的材料，不读取整个旧池。不同历史回答中的同名 E/R 编号始终以 runId 区分。

程序验证引用与原文/资源快照的对应关系，遵守当前所选文献范围，按稳定 ID 和版本合并到本轮材料池，重新绑定 E/R 编号。生成表 ID 也重新分配。只改写时使用保存的结构化 sourceBlocks 和重绑后的引用，并禁止新增原回答未引用的证据；科学论断是否被正确理解仍不由此结构校验保证。

历史资源只在实际作为模型图片输入发送后，才允许视觉模型在正文插入原图。表格与图片作为材料不等于必须在正文展示，沿用综述资源块协议。

### 路径与轮次

- 问候或澄清：由回答模型读取对话上下文回复，不要求文献索引准备就绪，不进行检索。
- 纯改写：取回所选历史回答/图表的结构和原有引用，保留出处；不新增向量查询。
- 追查依据：先读取历史原文并判断是否足够；不足再生成新查询。可以继续读取其他历史引用。
- 新研究追问：结合历史生成独立可理解的 query；可同时读取旧证据。
- 最低轮次只约束实际的新检索。一旦启动新检索，仍遵守最少/最多轮次；取回历史证据不算一轮检索。材料有局限不自动否定模型的充分性判断。

只有结构不完整、快照缺失或超出文献范围的历史回答，不能直接保留引用进行纯改写；程序会说明原因。不会按 PMID 猜测无法恢复的引用绑定。

### 多对话同时生成

文献检索聊天和文献问答均允许不同对话同时运行，应用不设置跨对话数量上限、不等待其他对话结束才发送请求。服务商返回的限流或连接错误归入对应对话。

- 问答每个对话保存独立的活动运行指针；`qa.statuses` 返回项目所有活动任务，`qa.status` 可按 `runId` 查询，停止操作也按 `runId` 定位。历史单任务指针仍可读取。
- 检索聊天的生成流由页面外的会话存储维护，按项目和对话分开。切换对话、离开再返回页面不会隐式取消生成；“停止生成”仅停止当前对话。
- 侧栏同时显示各个正在运行的对话。其他空闲对话仍可新建、发送、复制、分支或删除。
- 同一对话内仍按上下文顺序生成，避免两份回答覆盖同一历史位置；对运行中对话的删除和复制保护只作用于该对话。
- 项目清理流程会检查所有问答任务，不再只识别最后启动的一项。

### 对话目录与管理

问答与检索助手统一使用紧凑侧栏，支持右键重命名、复制、删除及勾选批量删除。顶部“对话目录”按用户提问编号，可搜索问题、定位历史消息、回到最新；跳转后不会被状态轮询拉回底部。问答失败重试在原消息位置更新，历次尝试日志仍保留。

## 人工质量评估示例

以下保留短链脂肪酸主题的可复用问题集，不是预设答案或已通过的评测记录。实际模型评估需另行授权；每次只向模型发送问题，不发送评估标准。

### 示例材料

可选用以下文献构造经授权的评估语料；不要求当前机器存在 gut 项目，也不假定已经获得全文：

- PMID 32901017，*Intestinal microbiota-derived short-chain fatty acids regulation of immune cell IL-22 production and gut immunity.* 若具备全文及图片，适合核对细胞类型、实验对象、受体与 HDAC 机制及图文关联。
- PMID 38565643，*Short-chain fatty acids: linking diet, the microbiome and immunity.* 适合补充整体机制背景，不能把综述对其他研究的转述自动视为本项目已读到原始实验。
- PMID 30915065，*Short Chain Fatty Acids (SCFAs)-Mediated Gut Epithelial and Immune Regulation and Its Relevance for Inflammatory Bowel Diseases.* 若具备全文及图片，适合区分机制解释与临床应用证据。

这些是评估时可检查的相关文献，不是强制答案必须引用的名单。检索仍然针对正文 chunk；本测试不要求用篇名检索。

### 初始设置与主问题

选择准备好的隔离评估项目和全部项目文献；保留当前检索轮次设置；自动补入整篇全文的功能已删除，无需设置开关。图像测试需要把实际支持视觉的回答模型设为视觉模型。模型名称或勾选本身不能证明它真的收到或理解了图片。

新建对话，发送：

> 肠道菌群产生的短链脂肪酸，尤其是丁酸，如何影响人源 CD4+ T 细胞的 IL-22 产生？请分别讨论受体信号、HDAC 抑制、下游转录调控，以及这些变化与肠黏膜屏障和炎症的关系。先聚焦人源细胞实验和临床证据；如果某条机制实际上只在小鼠或体外实验中得到支持，请明确区分，不能把机制证据写成已证实的临床疗效。

这道题能拆为不同证据维度，又有明确的“物种—细胞—机制—结局”边界。它尤其适合观察模型是否把不同实验的证据拼接成一个不存在的完整结论。

### 不同类型的追问

主问题回答成功后，复制该对话，每类追问在一个副本里测试。这样每次都基于同一份正式回答，不会被其他测试追问改变语境。最后再做一次连续追问测试。

| 类型 | 可直接发送的追问 | 预期行为与重点 |
| --- | --- | --- |
| 简短但需要新检索 | 那小鼠呢？ | 从历史解析为“小鼠中 SCFA/丁酸—CD4+ T 细胞—IL-22 的证据”，检索小鼠实验；不能当成询问小鼠常识，也不能只换物种名称。 |
| 增加细胞对象 | 那 ILC3 呢？这些机制和 CD4+ T 细胞一样吗？ | 沿用 SCFA/IL-22 主题，为新细胞对象检索；特别检查 ILC 与 ILC3 是否被无依据地等同。 |
| 纯压缩 | 把刚才的回答压缩到约 200 字，保留关键引用和物种限制，不增加新事实。 | 使用正式回答与其引用绑定，不启动向量检索；不受最少检索轮次强制约束。删减论点可删对应引用，保留论点不能错绑来源。 |
| 纯改排表格 | 只根据刚才的回答整理成表格，列出实验对象、细胞类型、干预、机制、结局和 PMID。原回答没写的内容标为“未提供”，不要补充新材料。 | 不检索；允许生成新综述表格；表内引用可追溯，不能为补齐表格而编造剂量、人数或实验结局。 |
| 追查依据 | 你刚才关于受体信号和 HDAC 抑制的解释，分别由哪些原文支持？请给出对应原文摘录，区分直接实验和作者讨论。 | 优先按上轮实际引用取回原文，而不是载入整个旧材料池；原证据不足才补检索。若正式回答没涉及这两项，改为粘贴其中一句真实论断再询问依据。 |
| 新增细节 | 上述关键实验的丁酸剂量、作用时间和对照组分别是什么？请区分小鼠体内、人源细胞体外和小鼠细胞体外实验；没找到的不要补猜。 | 这是新增事实需求，不能误判为纯改写；可复用历史证据并补检索，不能让表格不同实验的剂量串行错配。 |
| 查反证与边界 | 是否有证据表明这些作用依赖剂量或炎症环境，而不是丁酸总能产生同样效果？请在本项目中找限制性或相反证据。 | 增加证据维度，应检索；不能把没有召回反证表述为不存在反证。 |
| 多层历史回指 | 对照我最初问的人源证据和你后来补充的小鼠证据，哪些机制两者都有支持，哪些只能在小鼠中成立？ | 在连续完成“那小鼠呢？”后使用。要找回不同历史回答的实际来源；已有证据足够可以不补检索，缺乏依据时应补检索或明确未知。 |
| 闲聊 | 谢谢，解释得很清楚。 | 简短直接回复；无向量检索、无旧全文或图表材料池载入。 |
| 限定范围变化 | 现在只看溃疡性结肠炎患者中的干预研究，能否证明丁酸通过 IL-22 改善临床结局？不要用小鼠实验或人源细胞实验代替患者研究。 | 新检索；对患者证据不足允许回答“当前项目材料不足”，不能由机制推断患者因果疗效。 |
| 原图按需展示 | 刚才的机制中，如果已有材料里有一张最能支持关键结论的原图，请说明它支持哪一句话，并在有必要时插入这张图。若你没有实际看到图像，直接说明。 | 检查模型请求里是否真正发送图片及其来源绑定；文字里提到图号不等于已经看图。原图成为材料不代表必须插入正文。 |

### 推荐的一条连续测试路径

主问题 → “那小鼠呢？” → “那 ILC3 呢？” → “把刚才的回答压缩到约 200 字，保留引用” → “你压缩后保留的第二个机制结论有什么原文依据？” → “对照我最初问的人源证据和你后来补充的小鼠证据，哪些机制两者都有支持？”

这能测试：短追问的语境补全、跨轮引用取回、纯改写后仍能追溯原文，以及更早轮次的指代。对“第二个机制结论”有歧义时，直接粘贴真实句子；不要把合理澄清视为失败。

### 如何判定问题在哪里

1. **路由与执行**：在“检索与核对过程”核实是否实际执行检索，而不是只看回答说了什么。纯改写与闲聊应为 0 轮；依据追问可能仅取历史证据，也可能补检索。耗时不能单独说明走了哪条路径。
2. **上下文**：查看本轮运行记录 `input.json.gz`（或旧版 `input.json`） 的 history 是否包含此前用户问题与成功的正式回答；不应把失败草稿当成已确认结论。复制对话后，应能解析同样的历史指代。
3. **证据复用**：需要历史依据时检查 `history-evidence.json` 与本轮证据记录。E/R 编号在新轮可以重新编号；应该比较 PMID、稳定原文块/资源 ID 及对应内容，而不是要求 E1 永远不变。
