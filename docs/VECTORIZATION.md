# 文本向量化与文本块调试

## 入口

- **文献库 → 浏览文本块 / 检索测试**：按标题或 PMID 选择文献，左侧列出实际文本块，右侧显示全文、字符数、Markdown 行号、metadata 和原文上下文。支持分页、复制、导出 JSONL。
- **设置 → Embedding 模型**：独立配置 Embedding 地址、模型、密钥、版本标识、批大小、并发、超时、RPM 和 TPM；与聊天模型配置分开。
- **项目模型绑定**：项目 `metadata/embedding-model.json` 仅保存配置 ID、名称、地址、模型和版本，不复制密钥。新建项目继承当时全局默认；修改全局默认前，已有项目固定原选择。设置页“将此配置用于当前项目”显式切换项目模型；不自动清空或重建向量库。服务商密钥、限速、批量和并发保持实时读取；同一配置改了模型身份后，已有项目仍需显式更新绑定。删除服务商配置不回退到另一模型，需重新配置凭据。
- **文献库 → 检索索引 → 建立 / 更新**：可以直接索引现有全文与摘要，无需重试缺失 PDF。
- **任务中心 → 文本向量化**：查看进度、停止任务、增量重试、打开索引报告。

点击“新建配置”后可选服务商预设，或手动填写。预设只填入公开参数，API Key 始终留空，不覆盖已有配置或自动切换当前服务商。支持基础地址 `/v1` 和完整 `/v1/embeddings`。

| 预设 | 模型 | 每批文本数 | 并发 | RPM | TPM |
| --- | --- | --- | --- | --- | --- |
| siliconflow | `Pro/BAAI/bge-m3` | 32 | 4 | 1800 | 450000 |
| jina | `jina-embeddings-v4` | 32 | 2 | 100 | 100000 |

这四个参数与自动速度开关属于各自配置，不是全局参数。两套预设默认开启自动速度；每批文本数、并发显示为灰色且不可编辑，保存的手动值不限制自动调度。关闭自动速度后恢复使用这些手动值。RPM/TPM 始终参与限速；自动调度也根据延迟、429、网络错误调整批量与并发。预设配额可按实际账号修改，并非服务商所有账号的统一配额。

自动模式按服务返回的实际 token 用量和成功请求延迟估算批量、并发，不把预留预算当成实际消耗。响应慢但成功时增加并发以覆盖等待时间；429、网络失败或临时服务错误触发共享冷却和小批探测，连续成功后恢复。目标是充分使用先触及的 RPM 或 TPM，而非强求两项同时满额。手动批量和并发不约束自动模式；为限制内存和线程占用，内部并发上限为 64，Jina 每批最多 128 条，其他服务最多 32 条，实际准入仍受剩余配额控制。

自动 token 预算优先沿用匹配且已校准的 bge-m3 tokenizer；Jina v4 使用官方固定版本、SHA-256 校验的 tokenizer JSON（约 11.4 MB，随应用内置、跨项目共享），按全文计数并留 5% + 每条 8 tokens 的余量。分词数据位于 `services/downloader/resources/jina-embeddings-v4/`，附官方来源、固定版本与许可文件；随 Python 服务一起分发，首次使用无需下载，也不向项目或缓存目录复制。不加载模型权重或执行远程代码。资源缺失、校验失败或其他未匹配模型回退为按 UTF-8 字节数加余量估算，不再把每个短文本都预留为 8192 tokens。实际 usage 会回填配额账本；精确 tokenizer 的 usage 超过预留时停止任务，保留此前成功向量，避免继续以偏低预算发送。未知用量的失败请求保留预算；跨一分钟仍未返回的请求也暂留预算，避免慢请求提前释放配额。显式 `conservative` 模式仍保留每条 8192 的旧行为。

RPM/TPM 使用共享本地账本、61 秒滚动窗口与请求间隔控制；服务端仍可能因账户共享用量、突发限制或自身负载返回 429，应用会遵循 Retry-After 并退避。调度修改不改变分块、Embedding 请求正文、缓存签名或已有索引，不要求重建已完成的项目。

Jina 地址为 `https://api.jina.ai/v1/embeddings`，新配置预设默认选择 `jina-embeddings-v4`；已有配置的模型和当前项目索引保持原样，不随预设更新迁移。模型列表实时获取，只保留支持文本输入的单向量嵌入模型，排除聊天、OCR、重排与 ColBERT 多向量模型。v3/v4/v5 按用途发送 `retrieval.passage`（文献）与 `retrieval.query`（问题），请求浮点向量并禁用静默截断。Jina 的协议签名独立于旧通用请求，旧 Jina 索引需更新；其他服务商的签名保持不变。

官方参考：[模型规格](https://jina.ai/embeddings/)、[模型 API](https://api.jina.ai/v1/models)、[限额仪表盘](https://jina.ai/api-dashboard/rate-limit/)。仪表盘与新版 API 文档的免费限额目前不一致，预设采用较保守的 100 RPM / 100000 TPM。更便宜的模型不代表赠送 token 数会增加，免费额度消耗以账号账单为准。

远程 Embedding 请求与模型列表读取遵循当前系统 HTTP(S) 代理及 bypass 规则，localhost/回环接口始终直连；没有代理时直连。每次请求重新读取代理，开关或更换代理无需重启应用。公共解析逻辑位于 `services/downloader/network.py`，与 LLM 和下载器共用，不改变 TLS 证书校验或向量缓存签名。密钥眼睛按钮点击显示、再次点击遮蔽；仅查看不标记为编辑、不保存，切换配置清除当前显示状态。

“验证连接”使用当前尚未保存的表单，向配置的接口发送一次 POST 请求。测试文本可编辑（1–1000 字符）；只发送该文本，不读取项目文献。成功结果显示模型、实际地址、向量维度和耗时；HTTP 200 但返回空向量/非有限数/错误格式仍算失败。该操作不保存配置、不建立索引、不自动重试。确认配置后点击“保存配置”。

文本块预览与关键词检索均在本地运行，不需要配置 Embedding。语义检索需要已建立的当前模型索引。远程 Embedding 服务仅收到 chunk 原文，不额外拼接论文标题或章节路径；查询时会收到查询文本。标题和章节路径保留为来源 metadata。

## 同版本重装与重新连接

保留完整项目目录后重新安装，应用从 `metadata/embedding-model.json` 读取项目模型身份；密钥和服务限速仍只保存在本机。文献库分别显示当前模型/材料的可用索引数、本地已保存索引及服务连接状态，缺少服务配置不清空已有索引，也不把它当成已连接。设置页预填项目原来的地址、模型名和版本，密钥需用户重新填写。

重新保存同一端点、模型和版本的配置，即使配置 ID、名称、密钥不同，仍自动连接并复用已有向量；Base URL 与完整 `/embeddings` 地址等价。若有多个匹配配置，须明确选择“将此配置用于当前项目”。原配置 ID 的服务地址若已改变，不会将新地址的密钥发送到旧地址。已保存的模型身份不随全局默认切换。

缺少配置或必要密钥时，本地文本块和关键词检索仍可用；建立/重建索引与语义检索会提示重新连接。新问题仍需同一模型生成查询向量。不同端点、模型或版本使用独立索引，原索引保留，切回后可复用；材料本身变化仍按正常规则更新。本地文件本来就缺失、已被清空，或跨版本格式不兼容，不属于此恢复机制。

## 按段落拆分

按空行分段，所有非空短段保留；超长段落按句号附近二分：

1. 用 `\n\s*\n` 按空行分段，去除段落两端空白。
2. 段落不超过 **8192 个 Python Unicode 字符**时保持原样。
3. 超长段落选择最接近中点的英文句号 `.` 分成两段，句号保留在前一段。忽略两边均为数字的小数点，且尽量避免生成不足 100 字符的段。
4. 二分后仍超长则继续二分；没有合适句号时按字符中点分开。所有非空结果均入库，不再设置最短字符门槛。
5. 不合并短段落，不增加重叠；标题与表格遵守同一拆分规则；参考文献已在清洗稿中移除。

章节、表格等分类仅用于 metadata 展示，不改变分块正文。用于 Embedding 的输入仅为原始文本块；标题与章节路径不拼入输入，浏览/引用/导出保留原块；该输入模板有独立版本签名。字符数不等同于 token 数；服务不接受的输入明确报错，不悄悄截断。

拆分版本变更会使旧索引显示“待更新”，更新时复用仍匹配的向量输入。

## 来源与 metadata

仅处理 `pubmed/current.xml` 中的 PMID。优先使用与当前 PDF 指纹、清洗规则和生命周期匹配的 Markdown。已有有效 PDF、但 Markdown 缺失或过期时，显示等待全文转换，不使用旧全文建立索引；没有有效 PDF 时可以使用 XML 摘要，明确标为 `pubmed_abstract`。

每块可查看：

| 层级 | 字段 |
|---|---|
| 文献 | PMID、DOI、PMCID、标题、作者、期刊、年份、ISSN、语言、文献类型、MeSH、结构化摘要 |
| 来源 | 项目、检索式来源/运行记录、全文或摘要、相对路径、当前 XML 校验值、JCR 多学科分区及参考文件版本 |
| 文本版本 | 文献版本、PDF/Markdown 校验值、Marker 引擎、清洗签名、拆分版本、不可变源文本快照路径 |
| 块位置 | 稳定 chunk ID、从 0 开始的 chunkIndex（界面从 1 显示）、父段落 ID、段内分块序号、前后块 ID、章节、类型、字符数、起止行/字符偏移、内容校验值 |

字符偏移使用 Unicode 码点，不是 UTF-8 字节或 JavaScript UTF-16 单元。界面已按相同口径定位。`pdfPages` 仅表示已知的文献总页数；现有 Markdown 尚无可靠的逐块 PDF 页码/bbox 对应关系，`pdfLocations` 留空，绝不由 Markdown 行号猜测页码。JCR 年份只有配置明确提供时才记录，不从文件名猜测。

## 索引与更新

- 向量只保存在 `vectors/chunks.sqlite3` 的向量缓存中，召回时直接做余弦排序；综述、问答和文本块调试检索读取同一份数据。当前不使用 Chroma；旧目录是否仍存在以本机为准。
- 通用配置默认每批 64 块、并发 2、超时 60 秒；新建时选择服务商预设会使用表中预设值，已有配置不覆盖。针对网络错误、429、临时 5xx 有限重试；无效向量、索引顺序错误、数量/维度变化拒绝入库。
- 成功批次及时缓存。单篇全部向量写入且再次核对文献版本后，才标记该篇已索引；失败不发布半成品。
- 地址以实际 Embedding 端点确定模型身份：`https://host/v1` 与 `https://host/v1/embeddings` 等价。读取与写入都解析历史缓存身份；优先使用完整端点缓存，不存在时沿用旧 Base URL 缓存，无需迁移或重新请求。模型、版本标识、协议与输入模板仍严格隔离；验证指纹仍绑定密钥。
- 相同模型/输入复用成功向量；修改 chunk 原文会改变对应向量输入，单独修改标题或章节 metadata 不改变向量输入。模型、服务地址、模型版本标识或 Embedding 输入模板变化使用独立索引。`chunk-body-only-v2` 与旧的 `title-section-body-v1` 隔离，升级后须重新建立正文向量索引。
- 文献移出当前 XML 时归档 PDF，校验备份 Markdown 原稿、清洗稿、图片和转换记录后删除活动文件；删除该 PMID 的块记录、所有模型的索引登记和无人再使用的向量缓存。其他文献仍使用的共享缓存保留。
- 索引登记、块记录与无人使用的向量缓存在同一事务内删除，没有额外物理清理队列。旧 XML 和运行日志不作为可恢复的索引备份。
- 重新纳入先恢复有效 PDF，再恢复兼容 Markdown；备份不匹配才重转。向量索引重新建立，生命周期编号阻止移出前的旧任务写回。详见 [生命周期](ARTIFACT_LIFECYCLE.md)。
- 已配置服务后，默认在 Markdown 批次完成时接续索引；可关闭自动选项。所有下载失败、没有 PDF 可转换时可直接接续摘要索引。停止转换不会自动接续。
- 停止索引会等待当前并发请求返回；退出桌面应用后不再继续下一轮。下一次“建立 / 更新”复用已完成部分。

索引任务与“清空索引”通过 `metadata/vector-index.lock` 互斥；语义检索只读 SQLite，索引进行中也可使用，但只返回已登记为最新的文献。

## 检索调试

关键词使用本地原文子串匹配；语义使用当前 Embedding 模型按向量相似度返回 Top K，不提供混合排序或重排。检索排除少于 100 字符的 heading，保留长 heading、短正文和图注；参考文献仅在 Markdown 清洗阶段处理。只查询当前 XML 内、版本有效的证据。结果显示 PMID、全文/摘要、原块、邻接块、metadata、排序分数和向量距离；分数不是答案可信度。

检索日志保留问题和返回的实际证据，为后续问答可追溯引用提供基础。问答和综述使用同一正文召回逻辑；完整图表按位置关系补入共享材料池。

## 文件位置

```text
ScholarNoteLM/config/embedding.json       # 系统配置，含密钥；不写入项目
项目/
  vectors/
    chunks.sqlite3                       # 文献版本、块、FTS、向量缓存、索引状态
    exports/PMID.jsonl                   # 按需导出：正文块与完整 metadata
    chunks/PMID.jsonl.gz                 # 显式无损迁移后保留的旧自动 JSONL
    sources/文献版本.md                  # 拆分对应的不可变文本快照
    manifest.json                        # 当前模型签名与拆分版本，无密钥
  metadata/vector-job.json               # 最近索引任务
  metadata/corpus-membership.json        # 当前 PMID、生命周期及待清理记录
  metadata/file-fingerprints.sqlite3     # 内容校验值缓存
  logs/vectorization-任务ID/             # worker.log、report.json、report.txt
  logs/retrieval/                        # 检索测试的证据记录
```

JSONL 一行一个 `{id, text, metadata}`，便于在编辑器中检查或后续分析。所有非空短块进入数据库，点击“导出 JSONL”时才写完整文件；重复导出同一 PMID 更新对应导出文件。同步、索引和浏览不再逐篇生成重复 metadata 副本。导出是静态快照，后续索引变化不会自动改写它。图表完整内容独立存储，块 metadata 保存 resourceIds；检索时补入 resources。详见 [图表关联证据](positional-evidence-resources.md)。

旧自动生成的 `vectors/chunks/*.jsonl` 可用 `scripts/compact-project-storage.py --apply` 无损压缩为 `.jsonl.gz`；默认不带 `--apply` 只读估算。压缩不读取模型配置、不重建向量，旧文件逐字节校验后才移除未压缩副本。文章移出集合时，其旧自动 JSONL 及压缩副本一起清除；`exports/` 内显式导出的静态文件保留。SQLite 的分块、输入及缓存签名均不变。
