# Agent 阅读与可选 RCS

> 本文为对应日期的历史实现记录，不是现行操作手册。当前问答见 [文献问答](LITERATURE_QA.md)，设置与清洗见 [精简记录](APP_SIMPLIFICATION_20260928.md)，运行环境见 [本地维护](LOCAL_MAINTENANCE.md)。

本次改造借鉴 PaperQA2 的检索、上下文证据和按需工具调度，在现有原文、Embedding、引用快照和对话基础上实现；不引入 PaperQA 依赖，不提供外部论文发现。目标是用户约 200 篇论文的固定项目库。用户指定范围是唯一论文过滤条件，不让模型先按标题/摘要挑论文来缩小检索库。

## 取证与控制

主题问答先规划问题，然后 Agent 根据真实原文/证据卡选择行动。公开工具为 `gather_evidence`、`read_context`、`find_in_sources`、`inspect_coverage`、`generate_answer`。兼容旧 `queries` 和 neighbors/section/exact/papers 参数，仍经过白名单、参数、范围和分页校验。工具是 JSON 数据，不要求模型支持原生 function calling；已有 JSON/完整 DSML 适配继续有效。

- `gather_evidence`：全范围有效向量余弦召回，只计算 query 向量，不重建文献向量。每 query 独立取候选，多 query 合并按块 ID 去重。
- `read_context`：相邻块、指定章节、整篇分页，8 块/页；不因已召回论文集合而限制下一次全范围召回。
- `find_in_sources`：精确子串定位；可选 PMID。无 BM25。
- `inspect_coverage`：准备、阅读、入池、引用与剩余预算，同时可分页目录。目录不是研究结论证据。
- `generate_answer`：完成取证，冻结本次可引用材料。也可由控制器的 enough 判定结束；证据不足、动作重复或预算耗尽时作有限回答，保留原因。

取消固定每轮“整理证据”调用、取消不同模型时强制“回答前核对”。控制器每次决策可看到真实文本，不只看到标题和证据编号。语义召回计轮数；读取工具另计步骤，因此向量轮数用完后仍可定位上下文。无有效新动作可以提前停止；不为凑轮数重复查询。步骤上限防止无限工具循环。

## RCS 开关

| 配置 | 默认 | 语义 |
| --- | --- | --- |
| `rcsEnabled` | false | 是否评分与上下文摘要 |
| `rcsCandidateK` | 24 | 开启时每 query 候选数 a |
| `topK` | 8 | 每 query 最多保留 b 块；关闭时直接召回 b 块 |
| `queriesPerRound` | 3 | 单步语义 query 上限 |
| `minRounds/maxRounds` | 1 / 3 | 语义检索轮数；阅读模式不强制检索 |
| `maxSteps` | 12 | 控制器工具步骤上限 |
| `toolsPerRound` | 6 | 兼容旧字段名，现指单步读取动作上限 |
| `evidenceConcurrency` | 3 | RCS/逐篇阅读并发请求数 |
| `contextChars` | 60000 | 单批/综合材料字符容量，不是输出 token 限制 |
| `verifyAnswer` | false | 可选回答后深度核查，累计最多 60 秒 |

关闭 RCS 时，主题问答不调用证据模型；直接使用召回原文。开启时，a ≥ b：对去重后的候选并发评估，以 0–10 的问题相关性排序，保留最多 b 个。query 用于召回，评估问题始终是用户问题及其追问上下文。相关性不代表研究质量或结论可信程度。

每块证据卡有摘要、研究条件、对应问题要点、direct/background/counter/limitation/irrelevant 关系、原文连续摘录和偏移。完整原文/PMID/chunk ID/文档版本仍由来源快照持有。反证可以高相关；不能只保留支持问题预设的材料。摘要与引用匹配仅验证溯源，不验证摘要语义一定正确。

有效相关卡先按评分排序，同分按向量相似度稳定排序。明确不相关或 0 分卡不进入池。格式/摘录无效的卡没有伪造的 0 分：作为未评分原文按向量顺序填补剩余额度，标记警告。可能不足 b 块。读上下文返回的原文不必再经 RCS，池也不受单 query 的 b 限制。

## 阅读模式与模型角色

- **主题问答**：向量取证 + 自主读取/补查。
- **单篇精读**：必须明确选择一个 PMID，对该篇所有已准备原文块分批阅读，然后按需补查。
- **项目概览**：逐篇分批阅读整个选定范围的已准备原文块；不会先用 Top-N 选论文或选块。每块都须返回阅读卡，无关块显式标记。缺失块、未准备论文、无效摘录标记为不可用/部分完成；只有完整处理的批次才计为阅读完成。

逐篇阅读是阅读/摘要任务，不做相关性评分，即使 RCS 开关关闭也需要证据模型调用。该模式耗时随原文规模增长，整个扫描不计向量轮数。范围内文本块须已在文献库准备；无需已有向量即可直接阅读，不自动建立索引。

检索规划模型控制 query 和下一步动作；证据模型负责 RCS 与逐篇阅读；回答模型综合。`evidenceProfile/evidenceModel` 是新增角色；证据与检索角色留空均继承回答模型。没有强制使用 flash/pro 或更便宜的证据模型。原双角色设置兼容。共享供应商的连接参数继续适用于该配置下所有模型。

## 恢复、溯源和界面

`<项目>/qa/cards/<hash>.json` 保存成功 RCS 卡，身份包括问题、历史上下文、要点、原文内容/metadata、模型指纹、提示/流程版本；不包含 API key 明文。无效卡不进入成功卡缓存。版本或问题变化不会复用旧卡。

每个运行新增 `completed-calls.json` 和 `query-vectors.json`。仅保存已完成、通过阶段协议的模型响应；卡还须通过摘录/字段校验。原文、参数、模型及流程签名匹配时，`qa.resume` 创建新的运行，沿原输入重放，复用完整匹配的已完成调用和查询向量，重试失败工作。已成功 RCS 卡独立保留。原运行仍可回看；恢复不改写旧回答或引用。输入快照保存 `resumeFrom`。输入变化禁止继续检查点，用户可重新生成。

网络错误不冒充格式错误；取消、原文变化、配置变化不被降级逻辑吞掉。控制器/阅读批次格式修复继续限制为每次最多一次、整次最多两次、累计额外等待 60 秒；并发阅读的修复排队共享预算。RCS 单卡格式失败直接保留未评分原文，不对几十个候选同时发起修复风暴。

UI 在输入区选择模式，在设置和模型面板开关 RCS；设置中配置 a/b、角色、并发和预算。过程显示 query、补查理由、阶段、来源 PMID 和供应商公开流式输出。证据面板展示卡片、分数/关系、条件、摘录与完整原文。数量分别显示范围内、读过至少一个完整块的论文、完整处理块、入池、实际引用；展开可看逐篇完成率。“已读材料涉及 N 篇”不等于 N 篇全文均完整完成，需看逐篇块数，摘要也独立标记。

容量不足时优先使用验证摘录，并在每个材料项标记节选；仍超出时记录省略编号。逐篇阅读的最终池按论文交错排列，避免前几篇占满材料。最终回答只能引用冻结后的实际材料，不可引用未送入模型的块；卡的原文支持被截去时去掉该卡。**逐篇读完不等于所有内容都能进入一次最终综合**，未纳入/未准备材料必须在解释覆盖时区分。

## 验证入口与限制

```sh
./scripts/npm-local.sh run build
runtimes/retrieval/bin/python -m unittest discover -s services/downloader/tests -p 'test_qa*.py'
runtimes/retrieval/bin/python scripts/test-qa-integration.py
PLAYWRIGHT_BROWSERS_PATH="$PWD/runtimes/playwright" TMPDIR="$PWD/tmp" runtimes/node/bin/node scripts/test-qa-ui.mjs
```

测试覆盖 RCS 开/关、a→b 与反证、坏摘录/坏 JSON、角色、并发、缓存失效、完整扫描、缺失原文、工具补查、预算、恢复、取消/来源变化、真实 Rust RPC/worker 流式输出、引用快照和界面操作。所有测试使用隔离项目和本机模拟模型，不访问用户 API 服务或改写用户项目。

本次验证：48 项 QA 单元测试通过；真实 RPC/worker 集成测试通过；Playwright 界面测试通过（含 RCS 开关和证据卡、项目概览、单篇范围、中断后只重试回答）；TypeScript/Vite 构建通过。构建仍有既有的大 bundle 提示。界面测试另发现并修复新建对话后立即输入可能被迟到清空的问题。

尚未进行真实服务速度/费用/医学研究质量评测。语义质量仍取决于模型、原文转换及分块，引用校验不是科学结论验证。未实现外部文献搜索、引用网络、笔记写入、多项目检索或 PDF 页码定位。未增加独立 reranker。
